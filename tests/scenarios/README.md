# Phase-2 representative-part scenarios

`examples/representative_parts.json` defines 30 stable cases across flange, shaft/sleeve, mounting plate, cover, and boundary categories: 18 supported, six expected rejections, and six extension candidates. The latter two groups are not counted as successfully modeled parts.

`examples/parameter_perturbations.json` contains 108 explicit executable perturbation/restore records linked from the 18 supported cases. Each record pins command IDs and versions, supplies full command parameters, identifies the zero-based edit target and nested parameter path, and records numeric baseline and changed BREP expectations. The original 78 multi-command records are now fully instantiated, including a radial through-hole shaft and a genuinely annular raised cover. `test_parameter_perturbations.py` runs every complete command chain, edits the target through the Command Bus, checks solid count, validity, volume, bounds, selectable references and audit preservation, then restores the original value. The radial cross-hole uses an independent perpendicular-cylinder integration with a 0.02 mm³ tolerance for OCCT Boolean error; other volume checks use 1e-7 mm³.

A lifecycle test runs one perturbed scenario for each of the 18 supported cases, checking selection, body-volume measurement, undo/redo, `.mc.json` reopen, and STEP solid/volume round trip. Expected rejections and extension candidates remain identified in the catalog; they are not silently treated as supported. Broader topology lineage and repair acceptance remains tracked by P2-12.
