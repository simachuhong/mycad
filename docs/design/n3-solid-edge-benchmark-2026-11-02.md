# N3 设计引用：Solid Edge 对标复评

日期：2026-11-02。范围为单零件 Ordered（有序）建模、面引用和失败恢复；不把 Synchronous Technology、装配或完整拓扑命名作为 N3 目标。本文是基于 Siemens 公开资料及 MyCAD 源码的设计评估，未操作 Solid Edge 实机，不能把推断写成两款产品行为一致。

## 范围补充：三维设计空间

本篇聚焦 N3 引用/孔工作流，不能作为完整三维建模对标结论。用户补充的场景内草图、多坐标系、基准平面与非共面空间草图详见[三维建模基础框架修订](../superpowers/specs/2026-11-02-3d-modeling-foundation-design.md)。E2/E3 已有成果继续复用；E3-B 的候选拾取/捕捉依赖 M0–M2 共享空间契约，不能仅靠现有视口预览叠层接入。

## 结论

原草案的“来源特征 + 角色 + 有限操作演化 + 安全失败”适合 MyCAD 的重放架构，但作为用户可用的 N3 还不充分。应将交付边界调整为：**一次真实拾取产生绑定 → 创建特征 → 修改上游 → 结果保持设计意图或给出可操作的失败 → 重新选择并原子修复**。至少要把孔的定位语义和面引用一起验收；仅证明面身份保持，仍可能把孔放到错误位置。

存档 v5 与顶层身份数组应保留为候选架构而非既定方案。先比较可用的版本化表示、完成嵌套存档与命令版本派发的兼容原型，再作 ADR 决策。N3 的基础内核可先独立验证，但不得把仅 API 的实验称为 Solid Edge 对标的用户功能。

## 原草案的关键缺口

### 1. 面身份与孔定位必须分别建模

目前 [`_hole_position_offset`](../../src/mycad/geom/_b123_features.py) 的 `center` 依赖当前面几何中心，`point` 是世界坐标且要求仍位于当前面上。上游修改或前一道切削使面形状变化时，即便映射到了原面，几何中心也可能移动；世界坐标点在面移动时也可能失效。孔可能意外移动、落在孔洞区域或失败。因此绑定新面引用不应悄悄改变旧 `center`/`point` 语义。

首批明确两种可验证意图：面心随当前面重新计算，以及相对创建特征自身局部坐标系的点（只支持可稳定构造坐标系的平面 box/cylinder 角色）。后者的坐标轴、原点、参数变化与法向规则须明确，定位点必须落在面有效区域；无法证明时失败。尺寸到边/基准、一般曲面 UV、径向孔及随草图工作的关联坐标应登记为后续能力，不能靠绝对点冒充。验证孔中心、法向、深度与体积，至少包含面被非对称切削导致几何中心变化的例子。

### 2. 用户选面与失败恢复不可只留 API

现有历史编辑已有预览和 Bus 修改入口，但不能由此认定已支持新绑定拾取、失败模型中的重新关联和完整影响预览。首个用户闭环需要：在当前文档拾取面时生成唯一来源绑定；创建前预览并显式确认；上游编辑导致引用失效时指明下游特征和参数；可在候选重放状态重新选择，预览整个下游结果，确认后由 Bus 原子提交，取消/失败保持原状态与审计。恢复界面放在 N5 实施可以，但 N3 用户验收必须依赖 N5；N3 内核里程碑单独标为工程验证。

候选模型和当前模型的拾取 generation、文档身份及修订号必须绑定到预览；预览期间原文档变化时拒绝旧确认。不能先提交失败的上游改动，再依赖用户恢复，因为当前 Bus 的编辑失败应回滚。

### 3. 来源模型与特征种类太窄

草案仅有原始 box/cylinder 角色且把孔生成面全部排除。这样用户无法可靠引用已建孔壁或真正的常用草图拉伸实体。首批至少明确：原始面可否在 `new`、`add` 等模式建立真实来源；多实体和布尔归并发生时如何处理；孔壁与草图生成面目前不支持并在拾取时告知。下一个能力切片优先评估拉伸生成面和孔壁；不因 Solid Edge 存在孔对象就假设能用 OCCT history 唯一命名。

必须在真实 kernel 输入形状上记录和消费索引，而不是依赖分别构造的两个形状碰巧面枚举次序相同。不同操作、清理和结果归一化之间检查输入/结果拓扑一致性；映射缺失或不确定即失败。需要用真实面定位和后继几何做断言，而非只断言索引范围。

### 4. 分裂与合并的失败策略需要细化

立即拒绝不确定的一对多/多对一是安全起点，但可能把常见修改变成不可编辑模型。建立统计和验收样本，区分操作日志的关系、引用选择所需的语义、约束和确切几何结果。可证明唯一继承时继续，不能证明时拒绝并进入人工修复。首版可保守拒绝所有分裂/合并，但这只是明确的功能限制；不得称为 Solid Edge 同等处理，也不得为关闭 P2-12 将所有退化情况统一成 ambiguous。

### 5. 方向条件与回放基准须精确定义

全局 `+Z` 只能用于未旋转基体；语义角色应以来源特征局部坐标系定义，方向后置检查应区分局部方向与世界方向。当前阶段若来源特征被变换，而变换 lineage 尚未接入，应安全失败。对于普通尺寸变更，成功不是“查到一个平面”，而是保留来源、局部角色、定位关系和下游零件几何。

### 6. 文件与命令版本是独立风险，不是对标结果

当前 v1～v4 命令字段严格，引用快照只校验 v4；默认派发取最新版，`feature.hole@2` 已用于草图孔。新增版本若直接成为默认，可能改变 CLI/GUI 和旧脚本行为。需要以可执行兼容矩阵先验证：旧 v1～v4 读写、升级、Save As、复制、嵌套来源与指纹、不同版本引用链、插件派发、undo/redo 栈及旧外层读取器拒绝新嵌套内容。比较顶层实例表、新格式命令字段等候选后独立决策；不得静默放宽 v1 校验。文件身份与命令身份分离，同一份文件 Save As 的内部相对引用需明确；外部伪造的同 UUID 数据不能被误称为可检测。

## 建议分阶段及验收

1. **E1 技术原型**：对真实 box/cylinder 及两次 hole/cut，以面来源、局部角色和真实后继形状验证成功、分裂、删除、合并及 unknown；验证孔位置关系。此时不声称持久或用户可用。
2. **E2 持久化决策和 Bus 闭环**：用兼容矩阵选格式并写 ADR；覆盖版本派发、保存重开、重放、撤销/重做、失败回滚和嵌套文档；每个结果验证面与孔中心/方向/深度。
3. **E3 用户闭环**：拾取、预览、提交、失败诊断、重选修复、确认/取消、历史审计；记录真实桌面交互。该切片与原 N5 合并验收，但不必合并代码任务。
4. **E4 对标复验**：指定 Solid Edge 版本、系统、Ordered 模式、样本及步骤，两边记录成功/失败、面、孔中心/方向/深度、受影响特征和用户操作。覆盖尺寸反转、局部点、非对称切削、孔面消失、分裂/合并、两次连续修改、保存重开与撤销；不能仅比较体积。

E1/E2/E3 通过只能声明限定零件和操作闭环；P2-12/19 与 Phase 2 发布门仍按项目原计划验收。Solid Edge 行为没有实机证据时标记“待验证”，不把 MyCAD 的保守设计写成 Solid Edge 的实现机制或承诺。

## E1 实施更新

2026-11-02 已完成测试目录内的有限几何实验，见 [E1 证据](../../.omo/evidence/n3-e1-reference-probe-2026-11-02.md)。多步切削、尺寸反转和局部孔位的几何验证支持继续 E2；原型需要调用方提供来源形状和坐标系，尚未验证持久身份或真实 Bus 重放。非对称裁切使面心 x 从 0 变为 -1.5，而显式局部孔中心仍为 (-4,3)，确认定位契约须独立设计。
