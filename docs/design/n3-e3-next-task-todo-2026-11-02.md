# N3 E3 任务记录与三维基础依赖调整

日期：2026-11-02。状态：E3-A 后端候选/原子提交基础已实现并通过定向验收，详见 [E3-A 验收证据](../../.omo/evidence/e3a-replay-candidates/acceptance.md)。本切片不含 GUI；E3-B/C/D、整项 E3 与 P2-12/P2-19 仍未完成。实现依据当前工作树中的 E2-A/E2-B 成果、[ADR-014](../adr/ADR-014-command-instance-identity.md)、[ADR-015](../adr/ADR-015-bound-face-hole.md) 和既有 [N3 对标验收目标](n3-solid-edge-benchmark-2026-11-02.md)。

## 结论

已完成 **E3-A：隔离候选重放与原子确认** 后端基础。旧文档可在候选环境中准备身份升级及绑定孔，已有历史可同时预演多处参数修改；只有完整候选重放成功、用户确认且来源状态仍匹配时，Bus 才一次提交。取消或失败不改变活动文档。定向验收见 [E3-A 验收证据](../../.omo/evidence/e3a-replay-candidates/acceptance.md)。

2026-11-02 用户补充三维环境草图、多坐标系和辅助平面缺口后，下一实施包调整为[三维建模基础框架修订](../superpowers/specs/2026-11-02-3d-modeling-foundation-design.md)中的 M0/M1 最小闭环，随后 M2 场景内草图与共享定位。E3-B 继续采用独立工作流模块、复用孔控件及对象捕捉 + U/V + 栅格开关，依赖这些共享契约；再完成 E3-C 失效诊断与有限重选修复、E3-D 桌面验收。本调整为方案，未新增实现。E3-C 必须先明确可重选对象的表达边界；当前 split/merged 的后继不能靠一个重选按钮恢复。

## E3-A 实施前的源码核对（历史记录）

下表记录当时确定 A1–A6 的依据；候选/事务部分已由 E3-A 解决，不能再次当作当前待开发项。GUI 及引用范围的剩余缺口继续有效。

| 入口 | 已有能力 | 下一步缺口 |
|---|---|---|
| `core/bus.py::prepare_identity_upgrade/apply_identity_upgrade` | 来源文档/修订绑定的身份提案；活动历史与 redo 同步升级；单独升级可回滚 | 升级与首次绑定孔是两个独立事务；不能先升级活动文档，再把取消建孔称为“完全未改变” |
| `app.py::preview_command_with_sketches` | 独立内核重放历史并追加命令 | 返回显示快照，未保留可供候选拾取/修复的会话；没有多命令编辑、失败前缀结果与提交凭据 |
| `ui/right_panel.py::HistoryEditDialog.preview_changes` | schema 校验、参数差异、下游命令数量 | 没有执行候选几何重放；“预览影响”目前不是几何成功证明 |
| `core/bus.py::edit_and_replay` | 单条改参、amendments、重放失败回滚 | 先改上游会因下游旧引用而失败；连续调用两次不能实现上游修改与下游修复的原子提交 |
| `ui/execution.py::_ExecutionWorker.run` | 串行工作线程、session 过期结果丢弃 | 异常被压成字符串；ordinal/reason/parameter_path 不再作为可操作数据传到修复界面 |
| `geom/kernel.py::interactive_face_binding` | 当前精确面 → 持久绑定描述 | 缺少 app 门面；不含来源局部框架、世界点到 uv 的转换接口 |
| `ui/viewport.py::selection_target_at` | 既有建模预览期间仍可选择当前已提交模型 | 不能把显示候选的覆盖层直接当候选拾取上下文；必须显式区分活动模型与候选模型 |
| `geom/design_faces.py::reference_for/resolve_position` | 有效 primitive 角色、固定局部框架与有限面校验 | split/merged 已将角色标为失效，无活面可重新 mint；现有 wire 无法表达某一分裂子面 |

另一个容易混淆的点：`interactive_face_frame` 和 UI `picked_face_frame` 服务于当前面的几何/点击位置，不是 E2-B 保存的来源局部框架。非对称裁切后从当前面心计算 uv 会产生漂移，E3-B 应通过几何端口转换，不能在 UI 推算来源中心。

## 路线取舍

1. 直接接孔工具栏：能较快展示绑定孔，但无法满足首次升级取消、失败模型重选和组合修复的事务要求。
2. 一次完成 E3 全部 GUI 与拓扑扩展：验证面过大，候选状态、命名扩展与交互问题难以分别验收。
3. **建议采用：候选/事务基础 → 绑定建孔 → 有限修复 → 桌面验收。** 每项有独立可验证结果，保留 E2-B 的安全拒绝边界。

## E3-A TODO（已完成的后端切片）

### A1 — 定义候选生命周期及中立数据

- [x] 候选绑定来源运行期 document_id、内容 revision、会话身份、候选 generation 和规范化修改摘要。Save As/切换文档/undo/redo/外部编辑使旧确认失效，即使命令实例 UUID 相同也不能跨文档确认。
- [x] 修改集支持“既有命令参数替换”和“追加新命令”；既有命令保留 ID/版本/ordinal，新增命令在候选内获得稳定实例 ID，重复预览不改名。
- [x] 区分有效、预演中、预演成功、预演失败、过期、已提交/已取消状态；失败、过期和重复消费不得提交。
- [x] 候选 DTO 只含中立数据；原生 Part/Face 留在几何与组合根管理的候选环境，Qt 对象只留 UI。

建议新增 `core/replay_proposal.py` 承载中立提案/结果，组合根与专用模块承担会话协调；避免继续把全套状态机堆进 MainWindow。名称与具体签名留给实施计划锁定。

### A2 — 构造可重复使用的隔离候选

- [x] 从活动历史、格式与 redo 信息准备候选。v4 首次绑定在候选中采用 E2-A 提案的确切 ID；活动文档仍为 v4。
- [x] 明确主 Bus 签名提案与隔离 Bus 的信任边界：不能直接在另一个 document_id/密钥的 Bus 上应用主 Bus 提案，也不能在 UI 直写 Document 以绕过校验。
- [x] 为多条待修改命令先形成完整候选历史，再重放一次；不能在候选上逐个调用会提前失败的单条 edit_and_replay。
- [x] 候选服务保留可重建的状态与自身拾取作用域。重新预演后旧 generation 的面 ID 一律过期；主模型的 runtime ID 不移植到候选。
- [x] 当前预览仍限制为受支持的内置可重放命令；遇到不支持的插件历史显式报告，不静默跳过，也不扩大插件执行授权。

### A3 — 返回完整成功结果或失败前缀

- [x] 成功结果包括完整候选显示快照与提交所需摘要。
- [x] 失败结果包括 command_id、版本、instance_id（若存在）、ordinal、parameter_path、reason、最后成功命令位置和候选 generation。
- [x] 失败前缀仅表示失败命令执行前的模型；下游尚未重放，不能标为最终几何。失败命令的局部副作用不得进入前缀快照。
- [x] app 候选 API 直接返回中立 `ReplayCandidatePreview`，供后续执行器/界面集成；本轮不接入通用 `ExecutionResult` 或 UI。
- [x] 取消、覆盖旧候选或会话结束时释放候选；任何旧回调不得覆盖新候选或活动文档。

### A4 — Bus 一次原子提交

- [x] 增加复合提案提交入口，校验来源身份、revision、提案内容、预演 generation 与一次性确认。明确复用现有确认机制的部分，不把单独升级提案当成建孔或改参授权。
- [x] 可在同一事务中采用升级 ID、追加绑定孔，或同时修改上游及下游参数。整个流程由 Bus 驱动，app 不直接写历史。
- [x] 推荐沿用 Bus 的受控重放提交，而不是由 GUI 直接替换内核和历史；提交重放失败则恢复活动文档及几何。
- [x] 既有 timestamp/confirmed_by 不覆盖；每条实际改参命令只追加一条 amendment，记录原因及原参数。预览与取消不追加 amendment。
- [x] 失败/取消保留格式、IDs、历史、dirty、redo 与几何；成功内容编辑按现有规则清 redo；单纯显式升级继续保留 redo。来源已过期时在重放前拒绝。
- [x] 通过既有事件事务发布一次成功修订，避免 UI 看见“已升级但孔未成功”的中间状态。

### A5 — 第一批验收反例

| 场景 | 必须观察的结果 |
|---|---|
| v4 文档含 redo，准备升级和绑定孔后取消 | 格式、已有审计、dirty、redo、几何不变 |
| 重复预览后确认 | 预览采用的来源 ID 与提交一致；实际孔中心/半径/深度一致 |
| 绑定孔执行失败或提交阶段故障 | 不留下 v5 半升级、amendment 或残留新孔；原 redo 可继续 |
| 上游 replacement 令旧来源 deleted，同时将下游孔改绑到新的有效 primitive | 单独上游改参失败；完整修改集预演/提交成功，原活动模型在确认前不变 |
| 任一后续命令失败 | 返回准确的首个失败位置和可用前缀；正式历史不变 |
| undo/redo/Save As/切文档发生在确认前 | 拒绝旧提案；同 UUID 不足以绕过文档作用域 |
| 修改 params 后复用旧成功结果，或连续点击确认 | 拒绝过期摘要/重复消费，不出现双重追加 |
| split/merged 旧绑定进入候选 | 保留原 reason，不伪装成可绑定；无 rank/最近面回退 |

建议新增测试：`tests/core/test_replay_proposal.py`（提案/事务/审计）、`tests/app/test_replay_candidates.py`（隔离会话）、`tests/geom/test_bound_replay_candidates.py`（真实几何）。依赖回归按 bus、command_identity、bound_refs、history_isolation、bound_face_holes 与 layering 收敛；本轮分析不重复执行已确认测试。

### A6 — 明确撤销语义与完成边界

- [x] E3-A 的“原子”表示提交整体成功或失败，**不等于增加一步撤销整次历史修复**。当前 undo 删除末尾命令并重放；它不会自动把多条 amendment 恢复为旧参数。
- [x] 本切片沿用现有历史编辑/undo 契约；如产品需要 Ctrl+Z 恢复整次修复，应先单列版本化修订撤销设计，不在 GUI 文案中承诺尚未实现的语义。
- [x] 形成 scoped 验证、失败注入和文档证据。E3-A 完成只关闭基础设施切片，不关闭 E3 或 P2-12/19。
