# 二维文字与字体单元测试及品控验收指导

版本：1.0；日期：2026-11-17；适用模块：独立二维草图文字与字体首批实现。

本文件供开发、自测及品控人员共同使用，规定测试输入、判定标准、覆盖缺口和交付证据。它是本模块的验收依据，不是验收通过报告。所有执行结果均须在验收记录中填写；开发阶段的通过记录可以按本文条件复用。

## 1. 范围与依据

本次验收覆盖 `document_kind=sketch` 的独立二维文档：TEXT、MTEXT、STYLE、系统字体枚举、TTF/OTF/TTC 应用字体导入、Qt 排版、画布编辑、属性与图层、常用变换、剪贴板、命令历史、原生存档及 DXF 交换。零件内草图和工程图纸面注释不因此获得上述对象权限。

依据按以下顺序使用：用户确认的范围与项目 AGENTS.md、[文字与字体设计](../superpowers/specs/2026-11-17-drawing-text-fonts-design.md)、本文验收条款。开发证据见[测试入口记录](../../.omo/evidence/drawing-text-fonts/readiness.md)，历史交互要求另见[独立二维交互验收基线](autocad-2d-interaction-acceptance.md)。实现代码只用于定位，不得以“当前就是这样实现的”取代预期行为。

首批边界如下：

- MTEXT 为统一样式；局部富文本、分栏、堆叠及 SHX 字形绘制不在本次完整支持范围。遇到相关 DXF 内容必须明确报告近似或不支持。
- 字体导入到应用用户目录，不修改操作系统字体安装；DXF 不嵌入字体。缺字体应保留原请求并允许替代显示。
- 暂存相切或关联阵列的复杂草稿，须先完成再执行文字与几何混合变换；拒绝必须发生在任何状态修改之前，并给出提示。
- 尺寸公差、形位公差、块、炸开、区域填充不属于本次验收。后续标注复用字体能力不代表已验收这些功能。

## 2. 测试分层与验收结论

| 层级 | 内容 | 可证明的结论 |
| --- | --- | --- |
| U 单元 | 中立数据、纯变换、字体服务、排版、样式对话框及隔离的 UI 控制器 | 被测单元在给定输入和资源条件下符合断言 |
| I 模块集成 | Bus、内核重放、存档、真实 MainWindow 接线、混合剪贴板、原生 DXF | 本模块关键链路与直接关联模块协作正确 |
| M 人工及平台 | 真实中文输入法、原生桌面、不同 DPI、外部 CAD | 指定环境下的交互和兼容表现 |

U 通过不能替代 I；U/I 通过不能替代 M。本文要求的模块集成验证只限直接关联链路，不扩大为全系统测试。

**单元品控通过条件：**全部适用 U 条款具备逐项证据并通过；全部 I 条款通过或有仍有效的既有证据；静态检查符合项目约束；无未关闭的 S0/S1 缺陷；其他缺陷如需带入下一阶段，必须由验收负责人书面接受。待补、阻塞及未经核对的跳过项不能计入通过。整项条款含多个子场景时，只有全部子场景满足才可关闭。

**交互及兼容验收通过条件：**除上述条件外，还须完成目标平台适用的 M 条款。若 M 未完成，结论只能写“单元及模块集成通过，交互/平台验收待完成”，不能写“功能全面验收通过”或“跨平台通过”。

## 3. 环境、基线与隔离

每份记录必须包含：提交 SHA、未提交补丁或补丁文件及 SHA-256、操作系统/架构、Python/Qt/PySide6/ezdxf 版本、`uv.lock` 状态、字体样本文件名/来源/哈希、Qt 平台插件、测试命令、起止时间与退出码。只记录分支名不足以识别当前大量未提交的实现。

- 使用项目现有锁定环境；执行命令带 `uv run --no-sync`，不为测试自动升级依赖。缺依赖时先记录环境阻塞，由环境准备步骤解决。
- 自动 UI 测试可使用 `QT_QPA_PLATFORM=offscreen`。真实输入法、原生窗口和 DPI 场景使用桌面环境，不能用 offscreen 结果替代。
- 字体导入、存档、DXF 和图片均使用临时目录；以 `FontManager(临时目录)` 隔离应用字体库。测试不得写入用户正式字体库或覆盖真实图纸。
- QApplication 按项目夹具复用；字体注册的进程级影响须纳入隔离，不能依赖用例执行顺序。剪贴板用例结束前清空测试 MIME，窗口交由 Qt 夹具销毁。
- 确定性字体测试使用固定且允许测试使用的字体文件。缺失样本导致 skip，应登记为“环境阻塞”；不能靠换任意字体就宣称相同排版结果。
- 无须网络服务或 CAD 后端才能执行的数据单元测试，不应额外引入这些依赖。分层检查沿用 `tests/test_layering.py`。

## 4. 固定样本与判定精度

| 样本 | 测试数据 | 用途 |
| --- | --- | --- |
| F01 单行 | `中文 ABC 0123 ⌀ ± °`，位置 `(10,20)`，字高 `4 mm`，宽度因子 `0.8`，旋转 `30°` | Unicode、布局与存档；符号缺字须按实际字体报告 |
| F02 多行 | `第一行 ABC\n\n第三行 123`，MTEXT 框宽 `40 mm`，行距因子 `1.5` | 显式换行、空行、自动换行与行距 |
| F03 字面格式 | 字符串包含反斜杠、花括号、`%%d`、`^` 和字面 `\P` | DXF 格式转义，防止普通内容被解释为控制码 |
| F04 字体 | 固定拉丁 TTF、覆盖中文的字体、OTF、TTC、斜体；每份登记文件哈希 | 导入、字体族/字形、集合字体、缺字及斜体外伸 |
| F05 错误资源 | 伪造 `.ttf` 字节、`.shx`、不存在路径、不可写目标目录 | 错误提示、回滚与资源清理 |
| F06 冲突文档 | 目标与来源具有相同对象 ID、相同样式 ID、仅大小写不同样式名，但字体不同；同名图层颜色不同 | 粘贴和导入冲突协调，不改变目标旧对象 |
| F07 混合对象 | 普通草稿、已保存线段、文字、图片及不同尺寸样式的标注 | 一次操作、撤销恢复和样式协调 |

上表 `\n` 表示构造字符串时的换行；F03 的 `\P` 必须为字面字符。固定 UUID 可用于局部夹具；新建或复制对象必须检查其身份规则，不以截图判断 ID。

JSON 往返、枚举、文字内容、样式引用、图层属性及对象数量要求精确相等。几何及 DXF 数值默认使用绝对误差 `1e-8 mm`、相对误差 `1e-9`，角度采用等价周期比较，绝对误差 `1e-8°`；超出时先核对单位、坐标和原生格式精度，禁止直接放宽阈值掩盖缺陷。布局比例使用同一字体同一环境的相对测量；光栅墨迹不得超出报告边界加 1 像素抗锯齿余量。跨平台不要求像素图逐字节一致。

字高定义为字体 cap-height 对应的毫米高度，不是整个包围盒高度；包围盒可包含下伸部和斜体外伸。MTEXT 两行基线间距按 `字高 × 5/3 × 行距因子` 判定，不能拿总墨迹高度直接替代。

纯变换可采用以下独立数值基准：位置 `(3,4)` 平移 `(5,-2)` 得 `(8,2)`；绕 `(1,1)` 逆时针旋转 `90°` 得 `(-2,3)`，原旋转 `30°` 变为 `120°`；绕 `(1,1)` 缩放 `2` 得 `(5,7)`，有效字高 `4` 变为 `8`、框宽 `40` 变为 `80`；关于 X 轴镜像位置得 `(3,-4)`，原旋转 `30°` 在可读策略下为等价 `330°`。用 `pytest.approx` 显式传入本文误差，不能只验证“结果与原值不同”。

### 6.1 DXF 交换专项

以下均为 I 类条款。测试必须检查 ezdxf 读取的原生实体和样式属性，再检查导回对象；只做 MyCAD 自导自入不足以证明原生交换。

| 编号 | 场景 | 通过标准 | 现有覆盖 |

### 6.2 集成断言要求

- 五条内部命令为 `drawing.text.add`、`drawing.text.update`、`drawing.text.remove`、`drawing.text.batch`、`drawing.text_styles.set`。TEXT/MTEXT/STYLE 的交互入口指二维画布命令栏；不能把其测试等同于终端 CLI 全流程验证。
- 原子失败前后应比较文字、样式、图层、几何、图片、命令历史及可撤销状态；仅检查抛出异常不够。涉及暂存草稿时还需比较草稿实体和关联状态。
- 对用户的一次混合操作，用文档操作级 `undo_operation()` / `redo_operation()` 断言完整恢复；不要用多次底层 `undo()` 人为拼出“一次撤销成功”。单个原始命令测试才使用命令级 undo/redo。
- 审计至少检查命令的 `id/version/params/ordinal/timestamp_utc/confirmed_by`，保存前后和重放后语义一致；无本次修改原因不扩展到其他模块的全量存档测试。
- I12 的直接回归候选包括 `tests/ui/test_drawing_clipboard.py::test_text_editor_shortcuts_keep_normal_text_clipboard`、同文件 `test_copyclip_and_pasteclip_commands`、`tests/ui/test_workspace_tabs.py::test_drawing_workspace_roundtrip_preserves_layer_ucs_and_command_history` 和 `tests/ui/test_saved_drawing_selection.py::test_scale_saved_and_draft_together_stages_one_history_step`。仅选本轮受影响或原证据不再适用的节点。

## 8. 执行方法与测试成本纪律

1. 确认本轮修改路径和待关闭条款，选择单个测试节点或直接受影响的小组。复用既有通过证据前，核对代码补丁、字体、环境和依赖是否仍适用，并登记复用理由。
2. 对“部分/待补”条款，只新增缺少的行为断言。错误路径须同时断言报错和前后状态不变，变换预期由独立数学结果计算，不复制实现算法作为判据。
3. 执行 scoped 测试并保存输出、JUnit 和退出码。仅收集成功、出现 passed 字样后进程崩溃、超时、exit 139、skip、xfail 或零用例选中，都不能计作通过。
4. 失败后先定位产品、测试或环境问题；修复只复测失败项及直接受影响关联项。保留原失败记录及修复后的证据，不覆盖为“首次通过”。基础设施故障与清理按项目要求追加到 ledger。
5. 汇总条款状态和缺陷，不为了得到一个漂亮的总数重复已确认且未受影响的测试。

示例命令在项目根目录运行，输出目录先创建：

```bash
mkdir -p .omo/evidence/drawing-text-fonts/unit-acceptance
uv run --no-sync pytest tests/core/test_drawing_text.py::test_styles_are_unique_and_mapping_is_strict -q -ra --junitxml=.omo/evidence/drawing-text-fonts/unit-acceptance/U04.xml
QT_QPA_PLATFORM=offscreen uv run --no-sync pytest tests/ui/test_text_style_dialog.py::test_unchanged_missing_font_request_survives_other_style_edits -q -ra --junitxml=.omo/evidence/drawing-text-fonts/unit-acceptance/U09.xml
uv run --no-sync pytest tests/formats/test_dxf_text_exchange.py::test_native_mtext_without_inline_width_ignores_style_width -q -ra --junitxml=.omo/evidence/drawing-text-fonts/unit-acceptance/X06.xml
```

示例不是要求重跑已通过项。每次使用独立 run 名保存输出，修复复测不覆盖旧证据。若一轮确需运行某个完整小文件，应说明它与本轮变更的关系；不得顺势运行整个 `tests/ui/`、`tests/` 或全树四门。

代码发生变化时，lint、format 和 strict typing 也按实际改动路径执行。单纯撰写本文件不触发产品测试。只有整个系统上线前，如确需多轮全量测试，先说明范围、原因和预计成本并取得用户明确批准；技能流程不能绕过该限制。

## 9. 缺陷等级与处理

| 等级 | 判据 | 验收处理 |
| --- | --- | --- |
| S0 | 数据丢失、文件损坏、跨文档污染、失败仍发布部分状态或绕过 Bus 写入 | 阻断；定位并补防回归断言后关闭 |
| S1 | 承诺范围的创建/编辑/字体导入/撤销/重开/DXF 主链路不可用，支持内容无提示丢失，崩溃 | 阻断；修复并定向复测 |
| S2 | 有明确绕行的局部交互或排版问题，未破坏数据 | 修复；如延期，须验收负责人记录影响、绕行和后续任务并明确接受 |
| S3 | 不影响正确性和可操作性的文字、间距等表现问题 | 记录处理决定，不以数量阈值自动豁免 |

任何缺陷涉及本文明确边界时，先区分“边界内行为错误”和“新增需求”；不把应当提示的兼容损失归为范围外而关闭。不得通过删断言、提高误差、增加类型忽略、扩大跳过条件或修改分层测试来消除失败。
