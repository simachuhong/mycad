# 草稿与已提交图元混合移动：历史边界

当前状态：混选移动已接入画布暂存事务；提交前源文档保持不变，完成草稿时通过隔离重放候选一次提交。验证范围和尚未覆盖的交互见下文。

## 约束

草稿有独立的可撤销历史，完成或保存时才提交为 `sketch.create`；已提交草图只能经 Bus 修改。一次混选移动必须同时改变两侧，一次撤销/重做同时还原两侧；取消草稿、失败、切换文档和保存重开不得导致一侧残留。不能把未完成的草稿静默提交到文档，也不能将后续草稿操作合并进移动后使一次撤销丢掉额外操作。

## 实现方案

将混选移动作为工作区内的暂存事务：保留原文档版本、草稿快照和所有受影响草图的局部状态；画布及捕捉使用与该事务同一代次的投影，原文档直到提交草稿都不被修改。隔离候选验证每次修改及约束；撤销、重做和取消切换完整的草稿与投影快照。其他编辑和文档变动须进入同一时间线或因状态过期安全拒绝，不能悄悄使用源文档旧几何。

完成草稿时，在隔离候选中顺序追加移动前的 `sketch.create` 和原子 `drawing.sketch.revise`，再重放混选移动后的独立草稿修改；一次提交全部成功后更新源文档。提交失败保留全部暂存状态。这样保存重开后的末次移动可通过重放撤销，并保留移动前草稿对象。多个混选移动、图层与约束修改、分支撤销及非相同局部原点都必须有明确顺序和失败处理，不可通过合并所有草稿变更来假装一次移动。

混选移动的候选提交会将低于 v6 的文档存档版本升级至 v6，以保存这一事务的可重放历史；旧版本程序对升级后的文件是否可读取，取决于其对 v6 的支持。

## 验证

自动化覆盖混选、跨草图、重复移动、后续草稿编辑、撤销及重做、取消草稿、约束拒绝、源文档或工作平面变化、保存重开与重开后的逐步撤销。隔离候选失败时源文档不应发生部分修改。自动化不能替代完整桌面交互验收；按用户指定以 Autodesk 官方文档及现有录像对照，录像未覆盖的细节在审计记录中标明。

`tests/app/test_drawing_sketch_revision.py` 覆盖底层创建、批量修订、失败回滚和保存重开；`tests/ui/test_saved_drawing_selection.py` 覆盖画布暂存事务及历史边界。
