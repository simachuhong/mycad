# ADR-007 GUI CAD 执行单元与关闭策略

Status: Accepted 2026-10-24

## Context

P2-09 在 Intel Core i7-7500U、4 逻辑 CPU、Linux x86_64、Python 3.12.3 与锁定 CAD/Qt 依赖上，
以 10/25/50/100 个切孔特征采集了端到端基线。完整环境、样本、分位数方法和原始数据见
[P2-09 基准证据](../../.omo/evidence/task-P2-09-end-to-end-performance.md)。

在 25 个特征时，打开、撤销、重做的 P95 已分别为 416、433、416 ms；冷网格单次为 278 ms。
在 100 个特征时，打开为 4.37 s、撤销为 4.01 s、重做为 4.31 s，单历史重建建模为 4.25 s。
100 特征场景的当前网格冷提取为 795 ms，精细容差冷提取为 2.15 s，中点历史态（ordinal 49）网格冷生成为 386 ms。冷网格各只有 1 次测量，
不将其称为 P95。以上任务会占用 GUI 线程并超过 200 ms 反馈门槛。

## Decision

1. 每个主窗口持有一个 `SerializedExecutionUnit`，使用单一 `QThread` 串行运行 GUI 发起的 CLI
   建模命令、已确认计划批事务、打开文档、撤销、重做、显式几何重建，以及历史特征网格预览。每次只允许一个在途操作；
   重复提交直接拒绝，不建立隐式队列。
2. 几何操作在 worker 上完成后预热当前视口网格，再向 GUI 线程发出冻结的 `ExecutionResult` 信封。
   payload 不含 Qt 对象；打开完成后才将冻结包装器 `LoadedDocument` 交给 GUI，后续模型写入仍只经
   worker。UI completion、文档绑定、面板和视口对象只在主线程更新；单文档代次标识使换文档前的迟到
   结果被丢弃。worker 只接收 core/geom 操作，不接收 Qt 控件。
3. 忙碌期间输入、计划执行/取消和其他 QAction 禁用，保留“退出”入口但关闭请求会被拒绝并提示
   当前操作尚未结束。操作开始后不提供中断：Command Bus 完成原子提交，或依照既有事务规则回滚；
   计划只能在开始前取消。此策略避免强杀共享 OCCT 状态。
4. 窗口正常关闭时只在 worker 空闲后停止并 join 线程。若 owner 被直接销毁，teardown 会请求线程
   在当前操作自然返回后退出并等待，不会终止正在运行的 OCCT 调用。
5. 发布预算按参考机锁定：常用拾取 P95 <100 ms；场景刷新 P95 不超过该特征规模基线的 1.25 倍，
   向上取整到 5 ms；打开/撤销/重做 P95 不超过各自基线的 1.25 倍，向上取整到 1 ms；建模单条
   命令 P95 不超过同规模基线的 1.25 倍，向上取整到 5 ms。峰值 RSS 上限为 1,024 MiB。
   硬件延迟预算用于基准报告，不以降低阈值的方式掩盖回归；计数型断言继续进入普通 CI。
6. 一个 >200 ms 的可见任务必须显示忙碌状态并保持重复提交保护。冷网格测量和参考机基线只能说明
   需要 worker；冷网格尚未形成 30 次样本的 P95 门槛。

## Consequences

- 25 特征起，打开/撤销/重做和冷网格操作在 GUI 线程外运行；显式历史树项预览生成的冷网格也使用该 worker；较小场景也共用相同串行路径，避免
  同一个文档在同步和异步写路径间竞争。
- 当前 UI 提供忙碌状态，不提供对 OCCT 调用的软取消。任务运行中发起的关闭会被拒绝；任务完成后
  用户可再次关闭。owner teardown 会在当前操作返回后 join，因此极端情况下 teardown 会等待该操作。
- 只有需要原生崩溃隔离或可中断执行的未来需求，才重新比较独立进程方案。
