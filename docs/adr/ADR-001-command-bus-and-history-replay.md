# ADR-001 命令总线与历史重放

Status: Accepted 2026-09-17

## Context

阶段 0 是 headless 可编程 MVP：无 UI 壳，以法兰验收件（外径 φ80 / 内孔 φ20 / 厚 8 / 4×φ6 均布孔 PCD50，需求分析书 §8）为牵引，打通"命令 JSON/CLI → 校验 → Command Bus → Document → geom 适配层（build123d 0.11.1 / OCCT 7.9.3 封层）→ STEP/STL + JSON 存档"的唯一写入路径。

技术路线 §2 的五条架构原则中，本 ADR 落实前三条：单一写入路径（一切改模型操作进 Command Bus）、多入口同源（CLI、未来的 Chat 计划与 UI 最终都变为同一类 Command）、计划与执行分离（Agent 默认只产出 Plan，用户确认后 Bus 才提交）。Document 为真相源，视口与结构树只是视图。

拓扑命名问题（TNP）是 CAD 行业的已知脆弱点：FreeCAD 1.0 的拓扑命名 V1 官方仅称"缓解、非解决"（E4）。MyCAD 的缓解组合是几何谓词选择器（禁止裸拓扑索引，A6）+ 历史重放 + 显式报错。undo 语义需要在"per-command 补偿命令"与"删命令 + 全量重放"之间一次性定夺：几何完全可由历史重建，重放比逐命令 inverse 简单可靠（A4）。

## Decision

1. **唯一写入路径**：一切改模型操作——单命令执行、undo/redo、批事务、历史参数编辑重放——只能经 Command Bus 提交；Document 的有序特征历史是唯一真相源，任何旁路写入都视为架构违规。
2. **undo = 删命令 + 全量重放**：撤销即从历史移除目标命令并对剩余历史全量重放；redo 对称地重挂命令再重放。不做 per-command inverse 补偿命令，也不做命令后 brep 快照缓存（R17 记录演进口：当大模型重放性能出现上界时，再评估引入快照缓存，见 ADR-002 的 v2 演进说明）。
3. **批事务 = 执行前快照、整体回滚**：一批命令在执行前对 Document 状态取快照，任一命令失败则整体回滚到快照，all-or-nothing，无部分提交、无"返回错误对象继续执行"的语义。
4. **重放引用失效必须显式报错并指向命令**：重放中命中 TopologyReferenceError 时，错误必须显式携带并报出引发失效的命令 id（FreeCAD E4 教训：在断裂点报错识别是拓扑命名缓解的第一目的），禁止静默选择错误目标或吞错。
5. **坐标与单位约定**：全局右手笛卡尔坐标系；长度单位毫米（mm）、体积 mm³、角度十进制度（键名带 `_deg` 后缀）。极阵列角度参考系为全局 XY 平面：`start_angle_deg=0` 对应全局 +X，正向为从 +X 朝 +Y（自 +Z 俯视逆时针），对 +Z / −Z 定位面使用同一全局角度定义、不做镜像翻转。一般斜面上的投影局部系（局部 X 取 +X 在面内投影、退化时取 +Y）列为阶段 1 演进口，阶段 0 不实现。
6. **对技术路线 §7"撤销补偿信息"基线的遵从方式**：CommandSpec 保留 `undo_compensation` 字段，阶段 0 唯一取值 `"history_replay"`。协议字段显式存在、语义统一为重放——这是对基线的遵从而非删除、更不是偏离：技术路线 §7 要求每条命令携带"撤销补偿信息"，MyCAD 以协议字段满足该要求并统一其取值语义（协议遵从，不计入偏离计数）。

## 基线偏离

本 ADR 记录基线偏离 ②（headless 投影）。一个偏离主题、两个组成项，合并记录于本段：

1. **Chat 计划确认的形态投影**：需求分析书 §8 验收标准第 2 条（`docs/需求分析书.md:169`）以"通过 Chat 生成计划 → 用户确认 → 执行成功"描述验收。阶段 0 无 Chat 与 UI，该确认流投影为 CLI/JSON Plan + 命令级 `confirmed_by` 审计字段：Plan 为纯数据结构（六态状态机 draft|confirmed|executing|done|failed|cancelled），确认以 `confirmed_by` 字段落档、可审计。这是形态投影，确认红线不降级——未经确认的执行路径不存在，F-AGT-06 的 headless 等价即"Plan 六态 + confirmed_by"（远程面边界见 ADR-004）。
2. **"简单预览 / 简单 3D 预览"后置到阶段 1**：需求分析书 §7 分期表把"简单预览"列为阶段 0 主要交付（`docs/需求分析书.md:157`），技术路线阶段 0 亦明列"简单 3D 预览"（`docs/技术路线.md:104`）。本计划将其后置：阶段 0 只交付 tessellation 内存数据接口（T2，可调弦差三角化数据），预览本体后置到阶段 1 PySide6 壳。注意区分：视口本体相关需求（F-MOD-03 结构联动 / F-MOD-04 显示模式 / F-MOD-05 基准）本就是基线自身的阶段 1 分期项，不属于偏离；登记为偏离的仅是基线明列为阶段 0 交付物的预览表述（显式延期需求登记表 F-MOD-02 行已同步注明）。

两项同属"headless 边界"这一个偏离主题：阶段 0 的交付面是 headless 内核，基线以交互形态描述的阶段 0 交付物，投影为其 headless 等价物或显式后置，均不在偏离计数中拆分为两条。

## Consequences

- 正面：写入路径唯一使审计（NF-03）与回放语义天然成立；法兰级模型全量重放为毫秒级（E11 尖刺实证），阶段 0 无性能压力；undo/redo/参数编辑共用同一重放机制，不存在三套语义漂移。
- 负面与上界：全量重放在大模型下有性能上界（R17）——接受为已知限制，演进口为命令后 brep 快照缓存（记于 ADR-002 v2），避免阶段 0 过度工程；重放要求每条命令都是"参数到几何"的可重算函数，插件命令若携带不可重放副作用将破坏该不变量（ADR-003 的 CommandContribution 契约对此约束）。
- 重放报错体验：引用失效时用户看到"哪条命令失效"而非"哪个拓扑实体丢失"，修复动作明确——编辑该命令参数触发历史参数编辑重放，修订留痕于存档 amendments（见 ADR-002）。
