# MyCAD 机械三视图：对标、现状与建议设计

日期：2026-10-27。状态：**评估与建议方案，待确认后实施**。

本轮只调查、评估和编制 Plan；没有实现投影功能、改变现有模型或重启 MyCAD。

## 1. 结论与需求边界

**建议建设“与三维模型关联的工程图工作区”，首个可交付版本完成单零件的基准视图、两个正投影视图、基础关联标注和纸张输出。** 现有二维绘图可复用交互和样式，但不能直接当作工程图数据模型。

用户已明确：

- 对标 AutoCAD、Solid Edge 的机械制图流程，先深度评估和制定计划。
- 草图与工程图分开。
- 中央画布用常驻 Tab 分为“平面草图｜工程图｜3D图”，便于切换和后续句柄操作。
- 既有交互要求继续有效：画布内直接操作、右侧可浮动功能页、紧凑底部信息/CLI/AI/计划容器。

本方案提出但**尚未视为用户已确认**的范围：

- 首版以当前 MyCAD 原生零件的已提交实体为源；整个零件投影，多实体时统一计算互相遮挡。暂不做装配、外部 STEP 导入或任意多个模型文件引用。
- 采用同一 `part` 文档中的模型内容与工程图内容分区；独立 `.my2d` 保持自由二维绘图含义。新增工程图页不会把草图对象转换成工程图对象。
- 工程图新标注默认“关联测量”，不反向驱动实体；现有平面草图“新尺寸默认驱动”的规则保持。
- 默认建议第一角法、主/俯/左视图；同时支持第三角法及左/右侧视选择。默认值是产品建议，不宣称已取得某一国标的完整合规认证。
- A4/A3 横纵纸张、可编辑简式图框/标题栏、标准比例、矢量 DXF/PDF 输出进入首个完整版本；复杂剖视、局部放大、GD&T、公差配合、螺纹规范画法、BOM 分阶段追加。

**可行性判断：有条件可行。** 已安装内核具备精确隐线消除接口；最重的缺口是工程图领域对象、可重放的关联引用、工作区生命周期和输出一致性。现阶段没有投影性能/正确率实测，不能给出“几天完成”或“已经具备自动三视图”的结论。

## 2. AutoCAD 与 Solid Edge 的实际做法

### 2.1 AutoCAD：以基准视图建立关联投影

典型流程为：选择模型 → 在布局中 `VIEWBASE` 放置基准视图 → `VIEWPROJ` 从父视图拖出投影视图 → 设置显示、比例并标注 → 模型修改后更新视图。`VIEWBASE` 提供方向、比例、隐线及相切边显示；投影视图默认继承父视图比例/显示，并按拖动方向预览和放置。[AutoCAD VIEWBASE](https://help.autodesk.com/cloudhelp/2026/ENU/AutoCAD-Core/files/GUID-E0F79E2F-8838-4470-B8D0-8626343A22D2.htm)、[VIEWPROJ](https://help.autodesk.com/cloudhelp/2026/ENU/AutoCAD-Core/files/GUID-DC444927-6392-4F3C-88FC-33BBDF9AC464.htm)

正投影视图维持父子对齐；移动父视图会带动子视图，移动子视图受对齐方向限制。比例或显示可以显式覆盖继承值。`VIEWSTD` 的默认投影方式影响新视图，第一角俯视图位于主视图下方，第三角位于上方。[Projected Views](https://help.autodesk.com/cloudhelp/2025/ENU/AutoCAD-Core/files/GUID-1317AAB6-6A6D-4B11-8AAE-471C461FB8C5.htm)、[Drafting Standard](https://help.autodesk.com/cloudhelp/2026/ENU/AutoCAD-Core/files/GUID-78FCF96E-2FB2-4A5C-88C8-264647D980C5.htm)

模型变更需要更新相关视图；过期状态有视觉提示。尺寸附着边被删除时，关联可能丢失，应让用户诊断和重附着。[VIEWUPDATE](https://help.autodesk.com/cloudhelp/2026/ENU/AutoCAD-Core/files/GUID-8C6FECB1-F8FA-4AD4-8843-A94D02119514.htm)、[更新与失关联说明](https://help.autodesk.com/view/ACDLT/2026/ENU/?caas=caas%2Fdocumentation%2FACD%2F2014%2FENU%2Ffiles%2FGUID-D33C9891-9930-44F3-9176-20C064577643-htm.html)（后一个链接是帮助站共享旧主题，不据此判断 LT 功能授权范围）。

另有 `FLATSHOT`：将当前方向投影结果生成二维块，可分解和替换。它适合作为静态结果导出经验；文档说明的是二维块，不能据此承诺它具有 `VIEWBASE/VIEWPROJ` 的父子更新机制。[FLATSHOT](https://help.autodesk.com/cloudhelp/2026/ENU/AutoCAD-Core/files/GUID-03023631-7EC9-4B03-98C7-86AEB18988B5.htm)

### 2.2 Solid Edge：独立 Draft 语义，关联三维来源

Solid Edge 的 Drawing View Wizard 从零件或装配选源、选择主视方向及附加视图，再在图纸上定位；可一次布置多个视图。官方实例也展示了从活动模型创建 Draft、选择主视和附加视图、模型更换后执行 Update Views 的流程。[Siemens 官方流程实例](https://blogs.sw.siemens.com/solidedge/changing-your-modeling-approach-for-better-designs-part-1/)

官方训练资料说明，视图布局选项跟随第一/第三角法，用户可在放置时修改比例；第一/第三角也是明确的绘图偏好。训练资料为 ST5 年代，仅用作流程说明，当前产品能力另以产品页核对。[Solid Edge Fundamentals，Creating detailed drawings](https://support.industrysoftware.automation.siemens.com/training/se/en/ST5/pdf/mt01413-s-1050_en.pdf)、[投影方式 API](https://support.industrysoftware.automation.siemens.com/trainings/se/106/api/SolidEdgeDraft~DrawingViewProjectionAngleConstants.html)

当前官方产品页列出由三维模型创建/更新标准及派生视图、过期提示、标题栏属性、尺寸和标注、不同质量视图等能力。它也展示了自动绘图增强，但这些不应直接转化为 MyCAD 首版范围。[Solid Edge Drawing and Drafting](https://solidedge.siemens.com/en/solutions/products/3d-design/cad-drawing-and-drafting/)

Solid Edge 允许检索模型尺寸及中心标记，但检索动作有具体类型/重复尺寸/隐藏线等选项；“自动三视图”不等于“自动生成完整可制造标注”。[RetrieveDimensions](https://support.industrysoftware.automation.siemens.com/trainings/se/106/api/SolidEdgeDraft~DrawingView~RetrieveDimensions.html)

### 2.3 应借鉴的规则

| 事项 | 对标结论 | MyCAD 建议 |
|---|---|---|
| 草图与工程图 | 建模几何、图纸视图、标注有各自职责 | 独立领域对象和工具上下文，共享必要绘制组件 |
| 放置视图 | 基准视图先放置，投影视图沿方向产生 | 画布预览、对齐吸附、点击放置、Enter 确认、Esc 取消未提交部分 |
| 比例/方向 | 属于视图/图纸属性 | 不能通过缩放实体坐标模拟视图比例 |
| 隐线 | 由三维遮挡计算，显示可控 | 可见线、隐藏线、相切线分开保存和显示 |
| 关联 | 父子对齐、属性继承、源模型更新 | 保存来源绑定与视图关系；明确过期/失败/失关联 |
| 尺寸 | 支持模型关联与图纸表达 | 工程图默认测量语义，驱动入口留给模型参数 |
| 编辑 | 视图、标注各有操作对象 | 视图框句柄移动/调比例；标注句柄移动文字/重附着 |
| 输出 | 纸张、比例、线型与标注共同组成图纸 | 预览、DXF、PDF 使用同一份冻结的图纸场景 |

我们借鉴流程与对象关系。已有软件仍使用部分向导/属性对话框；本项目按用户要求将高频操作放到画布和右侧非独占面板。

## 4. 三种建设路线与推荐

| 路线 | 能得到什么 | 代价与局限 | 判断 |
|---|---|---|---|
| A. 静态三向投影转二维线 | 类似静态投影输出，可继续手工改线 | 关联、父子视图、模型变更和尺寸生命周期需另建 | 可作后续“解除关联/导出副本”；不作为主路线 |
| B. 同一零件文档内的关联工程图 + 三工作区 Tab | 模型、草图、图纸职责分开，共享来源和命令历史 | 需要工程图对象与非几何命令路径，但无需先解决跨文件依赖 | **推荐首版**，最符合用户最新 Tab 建议 |
| C. 独立工程图文件引用多个外部模型 | 接近完整 Draft 文档管理，便于独立发图和装配 | 额外需要文件依赖、稳定身份、缺失/移动/版本冲突、多文档执行上下文 | 首版稳定后扩展；不提前占用新扩展名 |

路线 B 不表示“图纸是草图”：两者只有共同的文档容器，没有共同的可编辑实体列表。工程图输出 DXF/PDF 供交付，原生编辑数据随零件保存。未来路线 C 可复用同一 DrawingSheet/DrawingView 模型，另加外部 SourceBinding。

## 5. 中央 Tab、交互与句柄

### 5.1 三个常驻工作页

`MainWindow → WorkspaceTabs → 平面草图 / 工程图 / 3D图`。每页创建后保持身份，切换不销毁/重建页面。

| 页签 | 编辑对象 | 点击/拖动结果 | 句柄 |
|---|---|---|---|
| 平面草图 | 草图图元、几何约束、驱动/参考尺寸 | 继续现有绘图与驱动流程 | 端点、中心、尺寸固定端等 |
| 工程图 | 图纸、投影视图、中心标记、测量标注 | 移动视图、放置标注、调纸张/比例 | 视图位置/对齐/等比比例；标注文字位置与显式重附着 |
| 3D图 | 实体、特征参数、模型选择 | 观察、建模、参数操作 | 现有拉伸/尺寸等三维操纵柄 |

Tab 同时具有稳定工作区标识 `sketch / drawing / model` 和 Qt objectName，供快捷键、CLI/未来 agent 定位。它们不是模型授权令牌；寻址工作页不绕过 Bus。

迁移需要逐项替换 MainWindow 中以 `centralWidget() is sketch_dialog` 判断当前工作区的分支，包括保存、撤销、选择、相机和快捷键。只给中央控件外包一层 QTabWidget 会使这些分支失效，因此工作区路由必须集中到 `active_workspace`，并保留旧动作入口的兼容委托。

- 切页保留当前缩放、平移、选择、纸张、右侧当前 Tab、工具状态、未提交草稿和内联输入值。
- 活动鼠标捕获/拖拽先结束当前捕获；未提交几何保持为草稿，不因切页提交或丢弃。尺寸编辑暂停时保留候选与输入，返回后恢复焦点；相关模型已变更则清楚说明预览过期，并要求重选。
- 工程图只使用已提交且成功重建的实体。存在未提交草图时显示“工程图对应已提交模型”；切页不自动完成草图。
- `drawing2d` 文档的“工程图”页可显示说明，生成按钮禁用并说明需要三维实体；不从任意平面图猜测三维形体。“3D图”可继续显示其平面几何空间预览，不能冒充实体模型。
- 各页上下文工具栏和右侧功能区随当前页切换；浮动页内面板在离开该页时隐藏，回页恢复。底部信息/CLI/AI/计划保持同一个容器与内容。
- 保存/关闭仍明确处理未提交草图。工程图已确认操作进入同一文档历史；全局撤销处理最新已提交操作，并展示动作名称。若平面草图有本地未提交历史，显式显示“撤销草稿”目标，不能在不可见页面偷偷撤销。

### 5.2 三视图操作流程

1. 在 3D 页确认实体；点击“生成工程图”进入工程图 Tab。已有图纸时切到该图纸，不重复创建。
2. 首次进入时在右侧选择纸张、横纵、投影法、主视方向和比例。默认显示待放置主视图，画布可见。
3. 鼠标移动预览，单击放置基准视图。预览阶段只产生临时对象。
4. 向上/下/左/右移动，按第一/第三角法推导相应投影视图并显示名称；吸附对齐，单击放置。提供“主＋俯＋左/右”组合预览快捷入口。
5. Enter 一次确认整组视图为一个事务；Esc 取消尚未提交的整组预览，已确认图纸不受影响。组合预览与逐个放置走同一后端。
6. 选中视图出现边框与句柄。主视图移动时带动对齐子视图；子视图沿约束方向移动。显式解除/恢复对齐；比例继承可显式覆盖/恢复。
7. 用现有风格的图中标注入口创建工程图标注；文字、引线位置可拖动。双击可改表达/精度，不默认打开三维驱动输入。
8. 模型修改后标记受影响视图，后台计算预览/更新；失关联标注显示警示，支持重附着或删除。输出前检查更新状态。

不提供任意 X/Y 非等比拉伸投影视图的句柄。视图比例改变的是投影呈现，不能改变零件尺寸。视图删除若有子视图/标注，必须先展示影响并整体可撤销；首版明确采用删除子树及其标注，后续再提供提升子视图操作。

## 6. 领域模型与实现边界

### 6.1 独立数据模型

建议新增 `core/drawing.py`：

- `DrawingSheet`：UUID、名称、纸张宽高 mm、方向、边距、标题栏、默认投影法和默认比例。
- `DrawingView`：UUID、sheet_id、`SourceBinding`、base/projected 类型、parent_id、显式正交基、纸上锚点、比例值/继承状态、对齐状态、显示策略。
- `SourceBinding`：首版仅 `current_part`、全体实体；同文档引用不依赖文件路径。后续外部来源另行版本化。
- `DrawingAnnotation`：UUID、view_id、种类、`DrawingGeometryReference`、精度、纸上文字/引线位置、样式和 DIM 层。
- `DrawingGeometryReference`：源语义锚点、几何种类/必要谓词、关联到投影曲线的角色和参数；不是运行期 TopologyId，也不是屏幕坐标。
- `DrawingState`：以上对象的纯数据集合与不变量，使用可重放命令构建。

建议新增 `core/drawing_projection.py`：只读 `ProjectedCurve`、`ProjectionResult`、`DrawingScene`。曲线应能表达线、圆弧、椭圆弧、带完整次数/节点/重数/权重的 B 样条；分类至少 visible/hidden/tangent，并记录轮廓来源。UI 可细分采样显示，保存和输出不能退化为屏幕像素。

`DrawingScene` 是某一文档/模型指纹/图纸版本的冻结结果，供画布和输出共同消费。它不拥有另一个可写模型。

### 6.2 Bus、内核和持久化

建议以 `drawing.sheet.*`、`drawing.view.*`、`drawing.annotation.*` 定义注册命令。参数携带持久 UUID，放置整组三视图使用现有批事务；用户确认后走 Bus 的现有执行/确认路径。

- `BuildKernel` 保持应用中的稳定门面，组合 `DrawingState` 及独立 drawing reducer。新增逻辑放专门文件，避免继续把大段纸张逻辑堆进 kernel.py/MainWindow。
- `kernel.apply` 的工程图命令分支更新绘图状态；`reset`/重放/失败回滚一起恢复。参数验证及对象引用检查先行。
- 明确分开文档 revision、实体几何 revision、工程图布局 revision。移动图纸视图不能重新生成 BREP，也不能让自己的投影缓存无限“过期”。
- 当前历史预览与 `state_id`/ordinal 存在联系。工程图命令必须保留历史序列与所需非几何检查点，不冒充新增实体特征；三维来源、BodyOrigin、选择身份不能因移动图框而被重分配。
- 首版优先使用已有 **v3 part**，将工程图对象写入新注册命令参数。旧 v1/v2 零件在首次需要持久工程图时走明确、非破坏的升级路径，保留审计六字段和 amendments；打开文件不改写它。
- 不给现有 v1/v2/v3 顶层私加 drawing 字段，不以 metadata 字符串藏第二份可写图纸数据。若实现探针证明确需新顶层持久字段，先补 ADR/新 schema 评估，再改变此方案。
- `drawing2d` 的限制继续明确；工程图命令首版只允许 part，不把内嵌三维建模指令塞进独立二维图。
- 计算投影、刷新缓存、显示过期状态是派生操作；修改纸张/位置/引用等持久数据才进入 Bus。保存不写入运行期 ID 或可变缓存。

### 6.3 投影与坐标

完整映射为：模型 mm → 视图局部 mm → 纸张 mm → 屏幕像素。

`paper_point = view_anchor + view_scale × projected_point`。尺寸数值来自模型/视图的未缩放测量，文字高度、箭头、线宽来自纸张单位。1:2 的 80 mm 边在纸上长 40 mm，标注仍为 80 mm。

- 用明确的右/上/观察法向构成正交基；不直接将 GL 相机 azimuth/elevation 当作工程图持久定义。
- 基准方向可选标准方向，或从模型面确定法向并由用户明确向上方向；法向和向上平行时拒绝。
- 第一角：俯视图位于主视图下，左视图位于主视图右；第三角：俯视图在上，左视图在左。左右视方向与摆放侧分别存储，切换投影法不能悄悄把左视变右视。
- 创建后更换投影法是明确的整图重排预览；调整默认设置不静默翻转既有图纸。
- 长对正、高平齐、宽相等由同一模型基准/投影变换维持；不分别按每个视图的包围框重新居中后凑位置。

### 6.4 HLR 与几何质量

OCCT 提供 BREP 和多面体两类 HLR；精确路线适合最终输出，多面体路线仅能作为明确标识的交互预览候选。[OCCT HLR 说明](https://dev.opencascade.org/doc/occt-7.3.0/refman/html/annotated.html)、[HLR 算法类型](https://dev.opencascade.org/doc/refman/html/_prs3d___type_of_h_l_r_8hxx.html)

本地 build123d 封装已使用精确 HLR，但只返回两组边，合并了 Rg1 相切边及轮廓。正式适配建议直接在 `geom/drawing_projection.py` 中分类提取 OCCT 结果，复用封装中的必要曲线修复处理；不能因返回了 Edge 就认定来源引用已完整。

需处理圆柱轮廓、孔的可见/隐藏段、圆角相切线、接缝边、相交与重合边、零长度段、闭合圆弧、椭圆和有理曲线。多个实体必须一起计算遮挡。轮廓线可能来自面而非原模型边，引用系统须表达这种来源。

若某曲线无法精确表达，输出前明确报告；受控折线近似必须记录容差且不得静默进入“精确机械图”输出。是否允许近似导出由用户明确选择。

### 6.5 关联标注和变更

首版有界支持：水平/垂直/对齐距离、圆/圆弧半径与直径、两直线角度、中心标记/中心线。首版不自动铺满全部尺寸，不推测制造意图。

- 复用 DIM 默认层、文字布局和画布放置方式，新增 DrawingAnnotation 类型；不要用 `SketchConstraint(driving=True)` 绑定生成的投影曲线。
- 线性值按所选视图投影方向计算；空间斜边投影长与空间真长不同，不能误标真长。直径/半径只在投影显示真实圆/圆弧、或已明确支持的模型语义标注入口使用；椭圆不能按圆标。
- 持久引用采用支持集合内的语义定位；源命令审计证据、几何关系与必要谓词共同判断。ordinal/遍历序号只能是线索；复制、撤销、重放后须重新唯一验证。
- 匹配失败或多个候选时，状态必须是 orphaned/ambiguous；保留文字布局和诊断，绝不按“最近一条边”自动套上去。
- 简单长度、孔径修改后仍能正确关联是首版验收。任意拓扑变化后的通用永久命名不在承诺内；删除边、合并面等走重附着。
- 工程图“改变尺寸驱动三维”后续可做显式“编辑来源参数”命令，但须知道是哪一模型参数并走对应模型 Bus 命令；不把改显示值当作模型编辑。

### 6.6 计算、缓存与输出

缓存键包含模型内容指纹、来源选择、显式视图基、几何/投影策略版本及内核版本。纸上平移、显示比例、文字布局不触发 HLR；模型或基方向改变需要重算。检测旧结果至少使用 session、模型指纹、view_id 与请求代次，session 相同也不能接收过期方向结果。

后台路径先复用串行执行器；P0 要实测 OCCT 调用是否释放 GIL、UI 心跳和长算例。现有线程只会丢弃旧结果，不会中断计算。若达不到交互门槛，改独立工作进程作为明确追加工作；禁止 terminate 工作线程。取消只取消未提交预览/结果接收，是否能物理中断必须诚实反馈。

输出复用同一 DrawingScene：DXF 中每个视图按局部真实 mm 建块，再在纸空间按比例放置；图纸线宽/字高按纸上 mm。工程图 DXF 是独立受测导出通道，不能绕过现有“单草图”限制硬塞三张草图。交换文件交付静态几何/标注，不承诺 AutoCAD 原生 VIEWBASE 对象或跨软件三维关联。PDF 必须为矢量纸张输出，不使用画布截图。

预览必须反映实际将写出的内容及比例；过期、失败、失关联、缺失曲线不能静默出图。默认拒绝最终出图并列出问题；若以后增加“草稿输出”，应有明确水印和用户动作。导出失败保留既有文件，沿用原子替换策略。

## 7. 风险与验证门

| 风险 | 为什么现有能力不足 | 必须提供的证据 |
|---|---|---|
| 方向/镜像 | 相机正交不代表纸上视图坐标正确 | 非对称带偏孔零件，第一/第三角，标准/自定义基准；对应点长对正/高平齐/宽相等 |
| HLR 曲线质量 | 光顺面轮廓/接缝与真实边不同 | 圆柱、圆角、通孔/盲孔、相互遮挡两实体；分类无漏线/重线 |
| 引用错误 | 运行期 ID 失效，生成轮廓没有天然原边 ID | 改长/改孔径仍唯一正确；删除/分裂/复制后明确失联或歧义；不得错误自动重绑 |
| 存档/撤销 | 新状态必须纳入 reset、重放、候选替换 | 保存重开、连续撤销/重做、失败回滚；草图/模型/图纸不分叉 |
| 尺寸比例 | 现有 scale 多为标注样式比例 | 1:1、1:2、2:1 数值一致，纸上字高一致；DXF/PDF 实测 |
| 异步结果 | 同 session 仍可能方向/来源变化 | 连续切视图/切文件/撤销，旧结果不会覆盖新视图 |
| Tab 生命周期 | 旧实现重挂中央 QWidget，浮动坞是独立窗口 | 未提交草图、尺寸输入、视图拖柄、后台计算期间切页，无丢状态/焦点/错误 Bus 目标 |
| 出图误报 | 现有预览按包围框适配，可能改比例 | 纸张尺寸与可打印区域、裁切、字体、线型的同源验证 |

拟定验收基准（**目标，不是已测成绩**）：

- 几何位置/长度误差采用 `max(1e-5 mm, 1e-8 × 模型包围盒对角线)` 的检查起点；先由 P0 对照内核容差审定，不能据此宣称制造精度。
- 标准图框/比例输出的纸上定位误差目标 ≤0.05 mm；线宽、字高和尺寸值分别验证。
- 参考工作站上常规 ≤1000 条 BREP 边的零件，三视图初次生成目标 ≤3 s、缓存命中布局操作 ≤100 ms；采集 p50/p95、内存峰值与原始几何复杂度，P0 后决定发布阈值和支持上限。
- 生成/更新期间 UI 应持续响应；用 100 ms 心跳记录最大停顿，连续 >250 ms 的主线程停顿必须定位，不能只看总耗时。
- 每个阶段对改动路径增量跑四门；集成完成后统一回归。当前没有为本轮评估重新运行所有旧测试。

样本集至少包含：不等边阶梯块＋偏心通孔、φ80×8 法兰/4×φ6 PCD50、带盲孔沉孔块、圆柱＋圆角、斜孔椭圆投影、两个相互遮挡实体、可接受的复杂曲线件、空/无效模型。以几何断言为主、固定视图截图为辅。

## 8. 范围、投入与发布判断

完整首版包含：同文档关联三视图、三 Tab、纸张比例、隐线/相切线设置、基础测量标注/中心线、变更与失关联诊断、存档撤销、DXF/PDF。剖视/局部放大/断裂/高级公差/GD&T/螺纹/BOM/外部关联/自动全标注列入下一批，不称首版为完整生产级制图环境。

计划分为 9 个有验收门的工作包，详见配套 Plan。估计 **34–54 人日**，按一名熟悉项目的工程师约 7–11 个工作周；是规划区间，不是代理执行时长承诺。HLR 溯源和线程响应尚未验证，P0 后重估；若需工作进程或更广拓扑命名，额外预算单列，不压缩进原区间。

推荐先批准 P0 技术探针和数据/交互边界，再按完整首版顺序实施。仅完成探针或静态三视图，不能宣称关联工程图已交付。

## 9. 本轮事实与尚待确认事项

已验证：上述本地接口/限制存在；官方文档支持对标流程；当前没有完整工程图实现。未验证：本项目 HLR 的正确率、性能、可追溯性、PDF 比例及新三 Tab 行为。没有拿第三方功能宣传替代这些验收。

实施前需要确认的产品选择：

1. 是否采用路线 B：首版随 `.my3d` 零件保存工程图，独立外链工程图放下一批。

3. 工程图默认关联测量、草图继续默认驱动的语义区分。
4. 首版包括基础标注和 DXF/PDF，暂不含剖视及高级制造标注。
