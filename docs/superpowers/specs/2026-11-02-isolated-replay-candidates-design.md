# E3-A 隔离候选重放与原子确认设计

日期：2026-11-02。状态：已批准；实施计划见 docs/superpowers/plans/2026-11-02-e3a-replay-candidates.md。

## 目标与背景

E2-A 已提供命令实例身份与显式 v5 升级提案；E2-B 已提供依赖 v5 身份的绑定面孔。E3-A 为后续绑定孔 GUI 和有限修复提供事务基础：用户可在活动文档之外组合多处既有命令参数替换、新命令追加及首次身份升级，重放完整候选历史；只有候选成功、用户确认且源文档仍是预演时的同一状态，原 Bus 才一次性提交。

取消、候选失败、候选过期或提交失败都不得留下活动文档变更。成功提交保留旧命令的 id/version/ordinal/timestamp_utc/confirmed_by，改参只追加一条 amendment；新命令获得在候选重放与提交间保持一致的实例身份。

## 范围

本切片交付可复用的中立候选提案/结果 DTO、隔离候选会话、完整历史预演、源 Bus 的一次性确认提交入口，以及对应的 core/app/geometry 验收。候选可表达既有命令参数替换和追加新命令；一次候选中的全部修改先合并为完整历史，再从头重放，不逐个调用会提前失败的 edit_and_replay。

候选状态至少区分准备中、预演成功、预演失败、过期、已提交和已取消。结果带来源 document_id/file_id/revision、应用会话身份、候选标识和 generation。重复预演沿用已暂存命令 ID 与审计数据；修改候选后 generation 前进，旧结果和候选拾取身份即失效。

成功结果含完整候选显示快照及确认提交所需的规范化摘要。失败结果含首个失败命令的 id/version/instance_id/ordinal、可用的 parameter_path、结构化原因、最后成功命令位置及候选 generation。失败前缀仅代表失败命令之前的模型；失败命令局部副作用和未执行的下游命令不得进入前缀快照。不要为填字段解析异常文本；原异常没有提供的定位信息保持为空。

候选 DTO 只含中立数据，不持有 Part、Face、Qt 对象或 numpy 数组。app/geom 管理隔离 kernel 与原生候选状态，并以候选自身的身份作用域处理拾取；主模型的 runtime 拓扑 ID 不可转入候选，候选重预演后旧 generation 的拓扑 ID 失效。取消、替换候选或结束会话时释放候选资源；迟到的工作结果不能覆盖当前候选或活动文档。

## 明确不包含

- E3-B 的绑定孔工具栏、完整拾取/孔位交互、预览确认 UI。
- E3-C 的重新关联 GUI、split/merged 后继面表达、拓扑命名扩展或最近面/rank 回退。
- 任意插件命令执行能力、插件信任策略扩张或跳过不支持的插件历史。候选遇到未支持的历史必须明确失败。
- 将一次复合提交变成单次 undo 的语义；继续遵守当前历史编辑与 undo 契约。
- 新存档主版本、旧档自动迁移、跨文档绑定或修改 E2-A/E2-B 的既定格式契约。

## 已核对的现状

- app.preview_command_with_sketches 已隔离 scratch kernel/document/Bus，但只重放现有历史并追加一条命令，完成后释放候选上下文并只返回快照。
- CommandBus.edit_and_replay 支持一条命令的 amendment、重放和失败恢复；连续编辑无法先形成完整候选历史。
- HistoryEditDialog.preview_changes 目前显示 schema 校验和参数差异，没有证明下游几何可重放。
- CommandBus 已有文档快照、redo 快照、事件事务、受控重放和失败恢复；Document.revision 在 Bus 提交、undo/redo、元数据变化时单调前进。
- BuildKernel.replace_state_from 可迁移候选 kernel 的成功状态，但 E3-A 不把 GUI 候选显示或主模型的拾取作用域混为一体。

## 实现路线

1. **隔离候选会话 API（已选）**：在独立 document/Bus/kernel 中构造并重放完整候选，源 Bus 对精确候选摘要签发一次性提交凭据，确认后由源 Bus 原子应用并受控重建。优点是取消前活动文档不动、支持组合改参/追加，也能复用到 E3-B/C；代价是需要定义候选生命周期和跨 app/core 的中立契约。
2. **扩展活动 Bus 直接批量编辑**：把多处改动放进活动 Document 再回滚。代码复用较多，但活动对象在预演期间已变，难以提供隔离拾取、稳定候选 generation 和无中间状态的确认流程。
3. **绑定孔专用事务**：只实现 v4 升级加绑定孔的特例。初始实现较窄，但不能支撑多条历史修复，也会把后续 UI 修复绑到一次性入口。

用户选择路线 1，因为它先完成可供后续交互复用的候选与事务基础，同时让 E3-A 保持在独立可验收的范围。

## 关键契约

### 候选构造与重放

- 候选以活动文档的命令、格式、文档类型/种类、必要元数据和 Bus redo 状态为基线。候选运行期身份必须独立于来源文档；内部命令实例 ID 按修改集复制或由来源 Bus 的显式升级提案分配。
- v4 首次绑定能力升级时，在候选中采用 prepare_identity_upgrade() 已签名提案里的确切 active/redo IDs；不把主 Bus 的签名提案直接应用到另一个 document_id 或密钥的 Bus。取消时活动文档仍为 v4。
- 先规范化所有替换与追加、构造不可变完整历史，再对该历史做一次完整重放。既有命令保留 ID、版本和 ordinal；新增命令的实例 ID、时间戳及确认审计信息在候选冻结时确定，重复预演和提交沿用相同记录。
- 只运行明确支持的内置可重放命令。预检遇到插件或其他不支持的历史时，以命令位置明确失败，不跳过、不尝试运行第三方代码。
- 几何失败时，保留中立失败信息和精确成功前缀快照。不得把失败命令部分执行后的 kernel 状态用作成功前缀。

### 过期与一次性确认

- 候选来源绑定运行期 document_id、file_id、内容 revision、应用 session identity、候选 ID/generation 和规范化修改摘要。相同命令 UUID 不足以跨文档或跨 session 确认。
- 候选成功后，源 Bus 为精确摘要签发不可伪造、一次性消费的提交凭据；候选参数、身份或 generation 被替换后，旧凭据无效。UI 是否展示确认由后续切片决定；调用提交入口本身代表用户已确认该结果。
- 提交前验证来源状态、generation、摘要、候选成功状态和凭据未消费。undo/redo、其他内容修改、Save As/文档切换及候选替换都让旧提交失效。普通预览、取消和失败不增加源 revision。

### 原子提交与审计

- 所有历史写入继续只经 CommandBus。源 Bus 在单一事件事务内校验凭据、应用身份升级/所有 amendments/追加命令、验证完整存档并执行受控全历史重建，整体成功后只增加一次 revision 并发布成功事件。
- 活动文档几何只在确认提交期间重建；候选预演从不替换活动 kernel。提交期间发生任意校验或重放失败时，Bus 恢复 Document、redo、dirty、格式、历史和原几何，并丢弃事务事件。若既有恢复重放也失败，沿用 Bus 的 unhealthy/poison 行为。
- 每个真实参数变更只生成一条 amendment，保留原命令 timestamp 与 confirmed_by；无变化不生成 amendment。追加命令只在提交后进入活动历史，不把预览身份记成 confirmed_by。
- 成功的内容编辑按现有规则清空 redo；只有显式身份升级而无内容编辑时，redo 及其升级后的 ID 保留。取消/失败保持原 redo。
- 复合提交表示提交整体成功或失败，不表示 undo 一次可恢复整批 amendment；UI 不得承诺该语义。

## 验收条件

- 候选替换上游命令并同时修复下游绑定孔：单独上游改参仍按原契约失败；完整修改集候选与一次提交成功，确认前活动 Document、redo、dirty、格式、几何均不变。
- v4 文档含 redo 时，可在候选中准备身份升级和追加绑定孔；取消后原档逐字段不变，确认后命令身份与孔引用使用候选里同一组 ID。
- 候选完整重放的任一位置失败时，报告首个失败命令与准确 ordinal/可用参数路径；成功前缀不含失败命令局部副作用，活动文档不变。
- 候选修改摘要被篡改、来源 revision/file/document/session 改变、generation 过期、候选失败/取消或凭据重复消费时，提交在重放前拒绝且不改活动状态。
- 重复预演同一冻结候选维持命令实例 ID 和审计数据一致；候选 generation 变化会使旧结果/拾取身份失效。
- amendment timestamp/confirmed_by 保留、原因和原参数只追加一次；失败与取消不产生 amendment。内容提交清 redo，纯身份升级保留 redo。
- 带未支持插件历史的候选显式失败，不调用插件 handler；现有单命令历史编辑、旧格式读取/保存、undo/redo 继续遵守原契约。

## 留给实施计划的事项

实施计划确定中立 DTO 的字段类型、候选服务放置及公开方法签名，复用现有 Bus/Document 机制而不让 app 直接写 Document。计划还需分解候选失败前缀的几何恢复方法、候选与源 Bus 的凭据接口、事件种类及失败注入测试，并根据改动路径运行 scoped lint、格式、类型与测试。E3-A 只关闭候选/事务基础切片；E3-B/C/D 和 P2-12/19 仍保持未完成。
