## 目标与范围

用户选择的基础实体面在编辑上游参数、完整重放时，仍引用同一设计对象；无法证明唯一对应时中止并给出位置与原因。显式最大面、rank 等查询仍按当前几何求解。首条可用链为 box/cylinder 的原生语义面，经 `feature.hole` 和 `modify.boolean_cut` 的操作演化，到后续 `feature.hole` 的目标面。支持多步 cut；已有 face/edge operation-local DTO 保留，首条产品闭环只承诺面。边和其他操作按相同规则后续扩展，不能据本次面闭环宣称 P2-12 完成。

不建立通用拓扑命名，不按坐标、距离、面积或 rank 猜测身份；不持久化 OCCT 形状、结果索引或运行时 UUID；不修改旧命令版本的含义。必须保留 Bus 唯一写入、审计六字段、确认和分层规则。

## 方案选择

1. 只增强几何谓词：兼容性成本低，但不能证明分裂/合并后的对象来源，不能满足目标。
2. **持久命令实例身份 + 创建特征语义角色 + 已支持操作的原生演化 + 后置检查**：用户已选择的有限范围方案；可以明确识别无法解析的情况，代价是需要版本化持久化和重放时维护映射。
3. 通用拓扑命名：覆盖更广，但超出阶段 2 范围和当前证据。

## 兼容与身份

提出独立 v5 存档决策：在顶层添加与命令顺序一一对应的 `command_instance_ids` UUID 数组；沿用 v4 的文档身份、kind、引用及六字段命令结构。v5 校验长度、UUID 格式、文档内唯一性；不改 v1～v4 的校验规则。命令实例 ID 在首次纳入 v5 时分配，编辑参数、undo/redo 和保存重开保持不变；删除再新建生成新 ID。历史 ordinal 只用于显示和数组定位，不能作为引用身份。Save As 为新文档分配 file_id，内部命令 ID 保持，引用按新文档隔离；跨文档命令 ID 相同不表示同一对象。

旧档不自动获得绑定语义：原有选择器和命令版本照常执行；只有显式启用新绑定能力时升级为 v5，在事务中为现有命令分配实例 ID。迁移后的保存保留原文件直到原子替换成功，失败保持文档及 dirty 状态；v1～v4 fixture 读取和原有格式保存语义不变。此升级策略及新版本需形成 ADR 并经 P2-24 契约测试；本设计不宣称 v5 已存在。

`DocumentReference` 当前只接受 v4 嵌套快照；v5 的实现必须同时支持嵌套 v4/v5，通过版本分派校验并完整保留被引用文档的身份表及快照指纹。引用 v5 快照时外层文档也须升级到 v5，避免旧版 v4 读取器遇到不认识的嵌套格式；不能把快照降级或丢失身份。绘图或草图引用、快照更新、来源图的循环检查、Save As 路径重定位与隔离重放都应覆盖 v5 来源。打开、保存和引用加载中现有的 v4 固定版本分支均需审计。

为 `feature.hole` 增加独立命令版本，其 `target_face` 接受显式的绑定描述，包含来源命令实例 UUID、创建特征的稳定角色、面类型和必要方向约束；数据与严格 schema 一同版本化。绑定是文档内相对引用，只在当前文档身份表中解析，不读取其他文档；Save As 保留内部引用，避免改写历史命令参数。选择入口须拒绝从别的文档构造绑定。若外部伪造的数据恰好含有当前文档已有的同一 UUID，则仅凭该相对描述无法检测其原始来源，不承诺此种检测。旧版 `feature.hole` 与所有已有查询保持原有行为。不可解析的来源、无效角色、前向引用和循环引用均显式拒绝。新版本命令只有在 v5 可保存时允许提交；确认摘要覆盖绑定描述。

注册表当前未指定版本时选择最新版：新绑定版本必须设计为显式 opt-in，并保留原默认版本的解析行为；调用方明确选择新版本才触发 v5。需要覆盖 GUI、CLI、批计划和插件派发，不能仅在 schema 上添加版本后让旧调用自动升级或失败。具体注册机制在实施计划中按现有兼容契约确定。

## 重放与演化

Bus 在创建/重放每条命令时把该条命令实例身份传给中立 handler 上下文；身份分配在执行前完成，成功才随命令记录提交，失败不留下孤儿身份。快照、候选重建、打开、undo/redo、批事务和恢复路径一起携带身份表；必须保持原有事件与审计语义。几何层按来源命令和角色在创建操作建立临时面映射：box 六个方向面、cylinder 的两个端面及侧面，仅在角色可唯一建立时接受绑定。

redo 栈必须与撤销的命令一起保管对应实例 ID；从旧格式升级时，活动命令和既有 redo 命令一并获得身份，事务失败时一起恢复，redo 后身份不变。重放时上下文不仅传入 handler，还须经中立 kernel 接口进入实际建模；审计 `BuildKernel` 的操作缓存、草图再生、引用更新内部重建及 `replace_state_from`，让每条记录的命令版本和实例 ID 随操作一致转移。暂不支持的重建路径必须安全失败，不得丢弃映射继续执行。

每条支持的 cut 消费前一结果的映射，并用 OCCT operation history 和同域清理 history 推导到新结果。单一 `preserved` 或 `modified` 且通过面类型/方向约束的结果可继承；`split`、`merged`、`deleted`、`unknown`、缺失历史、后置检查失败和不支持的中间操作均产生定位明确的错误，不对候选排序兜底。生成面暂不作为可持久来源；首版不要求从 hole 工具面建立角色。多次切削的映射逐步推进，每步映射的索引只在当步使用。解析在相应命令执行前进行，重建每次从持久角色和命令历史重新计算，运行时缓存不写入文件。

如首版无法证明多实体创建与合并操作的来源，应将该操作标为不支持并安全失败；测试必须证明相同几何对象不会被误认。支持范围仅按实际通过的构造及操作登记。设计错误应包含命令 id、ordinal、参数路径、结构化原因及可用的候选数/演化依据；不能降低既有错误定位能力。

提供从当前 viewport 拾取的 live `TopologyId` 生成绑定描述的中立 API，沿当前 lineage 逆查唯一的来源命令实例与原生角色；验证 generation 和当前文档归属。没有唯一来源、生成面、合并面或不支持的历史路径必须拒绝生成，不能把查询 rank 转成绑定。首版可通过 API 和真实 Bus 命令建立闭环；GUI 中完整的重选、预览和修复流程属于 N5。

## 事务与验收

- E07：同一模型中不同对象尺寸排序反转，查询可以改选；绑定引用保持来源或给出定位失败，绝不静默指向另一对象。支持范围内的唯一对应必须成功，不能一律报失效。
- box/cylinder → 两次 hole/cut → 绑定孔：验证原面唯一保留和修改、孔位置、重放后的几何意图；两次操作均须有演化证据。
- 从拾取面生成绑定描述并提交；检查生成面、非唯一来源和过期拾取均被拒绝，验证不能用查询 rank 假装绑定。
- 分裂、合并、删除、缺失历史、同形候选、未支持操作及无效/前向来源：安全失败，错误指向具体下游命令和参数；选择入口拒绝跨文档绑定。失败的 edit/execute 保留命令历史、审计、几何、dirty 和 redo 状态。
- 分别验证首次执行、上游改参、undo/redo、保存重开、不同文档隔离；编辑保留原 timestamp 并追加 amendment。旧版命令与 v1～v4 归档保持原行为，新旧版本不能静默混用。
- 测试覆盖 schema/迁移、Bus、真实 OCCT 映射、场景及分层；先做失败测试，再实现。按改动路径运行 ruff、格式、basedpyright 和 pytest；最终全仓四门留到阶段集成。
