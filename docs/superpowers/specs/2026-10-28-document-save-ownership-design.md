# 文档归属与存盘设计（含未来装配）

状态：用户已于 2026-10-29 确认详细设计和实施计划；实施与审查修正已完成，验收见 `.omo/evidence/document-save-ownership/acceptance.md`。设计日期：2026-10-28。

## 用户已确定的规则

- 独立平面草图、工程图保存为 `.my2d`；三维零件保存为 `.my3d`。
- 采用“独立二维文档＋模型内部草图”：建模内部草图随所属模型保存。
- 必须处理平面草图、工程图、三维模型同时未存盘的情况。
- 参考 Solid Edge 与 AutoCAD；预先考虑未来 assembly 装配文档。
- `.masm` 继续作为未来装配格式；本次不交付装配建模、约束求解或装配文件读写。

## 当前问题与边界

`MainWindow` 当前绑定一个 `LoadedDocument`、一个内核、一条历史、一个
`_document_path`。三个工作区都是该文档的视图。ADR-011 明确区分不可变的
`part`/`drawing2d`，ADR-012 将工程图保存在当前零件历史中。
因此仅按激活页修改后缀会产生文件类型与内容不符、其他内容错误清脏、重复覆盖等问题。

本设计替代 ADR-012 的“工程图与零件同档”存盘决策；保留 Bus 唯一写入、完整历史
重放、审计六字段、分层约束和旧格式只读兼容。现有混合存档必须经过明确迁移，不能
在点击工作区时直接修改 `Document.document_type`。

## 方案比较与选择

1. **单一项目档，按工作区改后缀**：改动少，但无法实现独立存盘和未保存检查，放弃。
2. **三个固定保存槽**：可以分别记路径，但未来多个零件及装配无法映射，放弃。
3. **独立文档会话＋文档间引用**：采用。用户已选择独立二维与模型内部草图的归属。
   以稳定文档 ID 管理任意数量的文档，工作区只是编辑入口。内部实现成本较高，
   但保存规则不依赖工作区数量，也可扩展到装配。

## 文档类型与界面路由

| 文档种类 | 原生后缀 | 主要工作区 | 内容归属 |
|---|---|---|---|
| 独立二维草图 | `.my2d` | 平面草图 | 图元、尺寸、约束、图层、历史 |
| 工程图 | `.my2d` | 工程图 | 图纸、视图、标注、文字、来源引用 |
| 三维零件 | `.my3d` | 3D 图 | 实体特征、内部草图、引用实例、历史 |
| 装配（未来） | `.masm` | 装配编辑入口待实现 | 组件实例、引用、变换、约束等 |

- 两种 `.my2d` 用存档内显式文档种类区分，不能靠文件名、命令猜测或最后激活页判断。
- 点击平面草图页进入独立二维文档；从零件的“编辑内部草图”进入时，清楚显示
  `内部草图 — 所属零件名`，保存仍指向所属 `.my3d`。这一区别不靠用户记忆。
- 切换工作区不丢弃任何文档或草稿，不隐式保存，也不让两个文档共用可变内核状态。
- 一个工作区可以在多个同类文档间切换，选择器显示文档名、种类和修改标记。
- 当前文件名、完整路径、修改标记均来自当前编辑文档；纯相机/缩放/选择变化不算修改。

## 保存、另存为与全部保存

### 当前文档

`Ctrl+S` 保存当前编辑文档。已有路径则原子覆盖；无路径则显示该种类的默认名称和
文件过滤器。独立草图建议 `untitled-sketch.my2d`，工程图建议
`untitled-drawing.my2d`，零件建议 `untitled.my3d`。

显式输入错误的原生后缀时提示并提供正确类型，不能将零件写进 `.my2d`；自动补齐后缀
后必须针对最终路径检查覆盖。不同已打开文档不能占用同一个规范化目标路径。

有效的草图草稿走既有串行工作线程与 Bus 提交，成功后写盘；未完成的交互提示完成或
取消，保留全部数据。写盘或提交失败不标为已保存，也不执行后续关闭。

### 另存为

为当前文档创建新文件身份与路径，成为当前编辑文档；原文件保持不变。现有引用者继续
引用原文档，不悄悄切换到新副本。需要替换引用时使用单独、明确的操作。
审计记录保留；复制的文件身份与历史内容身份分开。

### 全部保存

处理所有有修改或已明确创建但尚未命名的文档。仅因点击工作区而显示的空白占位页
不生成文件。先完成各文档可提交的草稿，再取得所需文件名，检查重名和覆盖，按引用
依赖顺序保存来源文档，再保存引用者。没有依赖的文档按稳定的打开顺序处理。

跨文件保存不伪装成原子事务：某文件失败时明确列出已保存、失败及尚未保存项目；
已成功的文件保持已保存，其余继续保留修改状态。取消文件选择停止本轮保存。

## 多文档关闭

关闭窗口显示所有待处理文档及其文件名/类型，支持保存选中、放弃选中、取消退出。
三个工作区都有修改时必须显示三份独立文档；模型内部草图与模型只显示一项。

“放弃”在整次关闭确认完成前只记录决策，不提前销毁内存文档。用户在后面的文件名
对话框取消，或任何保存失败，窗口继续打开，之前选择放弃的内容也仍在。
仅在保存请求全部完成且每项都有明确处理结果后，才关闭线程、投影进程和窗口。

## 来源关联与重放

每个可编辑文档有稳定 ID；文件路径只是可变化的定位信息。引用记录至少区分：
目标文档 ID、期望种类、相对路径（适用时）、引用的对象 ID、采用的来源修订/指纹。
工程图引用零件/二维草图，零件可将独立二维图作为有来源的内部草图实例使用。

二维草图用于建模时，内部实例携带被采用版本的可重放数据。工程图同样携带所采用
来源版本的重放数据，以便来源未命名、被移动或暂不可用时仍能打开已保存内容。
源文件更新不会在重放途中隐式改变模型；明确的“更新引用”经 Bus 写入新的采用版本，
可撤销、可重放。来源 ID 不符或缺失时显示关联状态，不能按同名文件自动替换。

实现侧选择：有关联的草图实例只读；需要在模型内独立修改时，用户先明确“解除关联”，
将当前采用版本转为模型内部草图，此后不再跟随来源更新。原生内部草图照常编辑。
本次不引入本地修改与来源更新之间的自动合并或冲突覆盖。

保留历史 JSON 与审计字段，不使用 BREP 快照替代真相源，不在 core 引入 CAD 后端。
新归属/引用语义使用新版本存档；v1/v2/v3 校验规则不放宽。加载候选文档及引用必须
先完成校验和隔离重放，成功后才加入会话；失败不能破坏当前已打开文档。

## 未来装配的预留契约

- `.masm` 是独立装配文档，不能作为 `.my3d` 的别名，也不能只是当前画面快照。
- 组件定义与组件实例分离：同一零件可以有多个实例，各自有稳定实例 ID 和放置变换。
- 装配保存自己的实例、约束、配置等数据；被修改的零件仍是独立待保存文档。
- 编辑零件的内部草图时，保存目标是该零件；编辑组件位置时，保存目标是装配。
- 依赖顺序按图处理，例如 `独立草图 → 零件 → 子装配 → 总装配 → 工程图`；
  不能按三个工作区的固定顺序保存。共享组件去重，循环引用明确拒绝。
- “另存装配”仅创建新的装配文档并保留组件引用；复制装配及全部依赖是未来独立的
  “打包/复制项目”操作，不能混入普通另存为。
- 相对路径、重命名/移动后的重定位、缺失组件、只读组件和多实例引用由统一引用层处理。
- 本次仅以抽象依赖图测试预留保存调度，不注册装配建模命令，不宣称支持打开 `.masm`。

## 旧档案与迁移

旧 v1/v2 按零件读取，旧 v3 按显式类型读取。旧档中的内部草图保持所属模型。
旧档内嵌工程图迁移为独立工程图文档并引用来源零件。迁移后的新文档显示待保存；
用户明确保存后才写入新格式，原文件不被静默覆盖或批量删除。
混合旧档中的独立草图意图不确定时，保守地作为模型内部草图保留，提供显式分离操作。

## 验收

1. 平面草图与工程图默认 `.my2d`；三维与模型内部草图默认 `.my3d`。
2. 三份文档同时有修改，保存一份后另外两份仍未保存，路径互不串用。
3. 全部保存处理首次命名、文件名冲突、取消、部分失败、来源依赖及共享来源去重。
4. 退出可逐项处理；任一步取消/失败都不丢失未保存或此前拟放弃的内容。
5. 二维来源→模型→工程图能保存、关窗、重开，来源更新通过明确操作进入历史。
6. 另存为不隐式改写引用者；旧档隔离打开及迁移可回退。
7. 多个零件的文档会话与抽象装配依赖图不依赖三个固定工作区。
