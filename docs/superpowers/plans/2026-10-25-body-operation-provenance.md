# P2-37 当前实体的来源与结果追踪（下一步）

## 已证实的剩余缺口

显隐、目标/刀具/种子名称、结果总数已实现；但操作结束后结构树只有“实体 N”和运行时 UUID，不能从当前实体看出它来自哪个创建/复制/布尔步骤。需要保留原范围，把这一点补上；不能用最后一个全模型 snapshot 的命令名冒充每个实体的来源。

## 拟定实现（实施前继续核对当前内核）

1. 增加轻量、不可变的实体来源显示 DTO：当前 BodyId、结果引用、产生该结果的状态步骤、该步骤的输入实体引用。这是历史操作输入关系，不宣称逐面拓扑贡献或装配持久 UUID。
2. 几何适配层按每次成功命令记录来源。对于与原实体 OCCT `IsSame` 确认相同的未改变结果，保留原来源；新/改变结果记录当前命令及其输入。布尔、变换、阵列输入使用命令中真实解析出的目标/刀具/种子；通用建模操作明确标为整个步骤的输入，不猜测哪个旧面贡献了新实体。
3. 只在成功候选安装后发布；失败不改来源。reset 清空、打开候选 replace_state_from 复制、undo/redo 经相同命令重建。尺寸驱动的全模型重建要单独处理：原内核中追加尺寸命令时，以该重建步骤和原输入关系产生新来源，不能采用跳过约束后的候选内核序号当作原历史序号。
4. 当前 viewport DTO 按 BodyId 携带来源，结构树在属性/提示中显示可读命令名称、步骤与输入；历史预览若未携带来源则不编造。要核对状态 ID 与 Document ordinal 的既有映射，不默认为相同。
5. RED→GREEN：箱体→复制→保留/消耗工具差集；不相关第三实体；通用阵列；失败回滚；尺寸重建；保存重开与撤销重做。来源断言与精确几何/实际选择同时核对。
