# 历史修订撤销实施计划（实现与专项验证中）

目标：按 [设计草案](../specs/2026-11-05-history-revision-undo-design.md) 支持一次撤销/重做历史修订和复合修复，保持 Bus 唯一写入及旧命令级 API 兼容。

1. 明确 ADR-001/008 的增补：运行期操作事务与命令级 `undo(n)` 的关系、重开边界、审计/dirty/revision、档案版本及身份升级不回退的规则。列出所有模型写入入口与不走 Bus 的文档元数据变更；不能仅覆盖 GUI 修改。
2. 先以 core 测试约束运行期操作历史：修订、复合替换/追加、普通命令、批事务的顺序；重做清除；旧 API 混用和外部 revision 变化；历史容量边界；旧档重开后的命令级回退。
3. 在 Bus 实施原子事务恢复和版本化操作栈。按原模型事件事务、重放及回滚机制处理失败；不能恢复旧 revision、复用过期候选、降级已升级档案或改变命令实例身份。
4. GUI 接入操作撤销/重做，保留未完成草图本地撤销优先级和异步执行互斥；补充历史编辑、绑定孔修复、二/三维切换、多文档、保存重开及工程图依赖的真实交互测试。
5. 跑受影响的 core、app、CLI、UI scoped 回归、分层及四门路径检查；对抗注入重放/恢复失败并核对命令、审计、格式、dirty、revision、几何和 redo。未通过之前不更新 U11 完成状态。

当前已接入会话内操作级撤销，验证进展见 [U11 证据](../../../.omo/evidence/ui-redesign/u11-baseline.md)；不承诺跨进程修订撤销或不可篡改审计日志。最终集成和人工验收仍未完成。
