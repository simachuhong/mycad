# 基准框实际裁切与自动布线保护不一致

**历史复现（旧算法）**：该脚本针对版本 25 及旧布线策略；旧历史按兼容要求保留原表现，因此仍会复现。当前新建自动基准采用版本 27 的算法版本 4，使用实际框边裁切检查；当前画布和 CADCraft 交换验证见 `../tolerance-gui-current-autoroute/README.md`。以下为原始诊断记录，不能据此推断新版仍有同一缺陷。

运行 `uv run python .omo/evidence/tolerance-datum-box-guard/reproduce.py`。在当前字体环境中，脚本创建带共享布局与版本 25 自动引线的基准，修订附着线后输出：

```text
box=5.212760x5.000000 target=(9.0, 1.0) path=((0.0, -1.8217060344121334), (-7.0, 0.0), (-7.0, -3.0), (9.0, 1.0))
visible_first_segment_crosses_arrow=True
```

这是确认缺陷的诊断脚本：当前版本输出 `True` 表示成功复现，修复后它会退出并提醒更新预期。脚本使用当前机器的默认字体度量，具体框宽可能因字体而变化；坐标和模型参数见 `reproduce.py`。问题在于框侧保护以基准插入点作为检查起点，而 `datum_leader_path` 按实际矩形中心射线裁剪框边；二者不相等。仅检查插入点到折点不能证明实际可见线段不穿越箭头。
