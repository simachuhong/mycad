# 文档归属与保存验收

2026-10-29，执行用户确认的详细设计及五步实施计划。

## 交付行为

- 独立平面草图、工程图分别保存 `.my2d`；零件及内部草图保存 `.my3d`。文档选择器支持多份同类文档，每份拥有独立内核、历史、草稿、视图、路径及修改状态。
- 保存绑定发起请求的文档；全部保存先处理草稿、收集所有路径，再按来源依赖顺序写盘。路径冲突在写盘前拒绝，失败仅保留成功文件的已保存状态，其余内容仍在内存。
- 退出清单支持逐文档保存或放弃；取消及保存失败不销毁任何文档。保存成功后遇后台视口刷新，会等待刷新结束后继续退出。
- 来源采用版本通过 Bus 写入历史；重开不依赖外部文件，更新和解除关联可撤销。打开时提示来源缺失、身份/种类不符等状态。重新定位及另存到新目录会正确记录来源路径。
- 内部草图可显式复制为独立二维文档，保留几何、约束、图层及平面，移除模型面支撑；原模型和历史保持不变。
- v1/v2/v3 混合档隔离迁移为独立待保存文档，原文件字节不变。保存后的 v4 迁移文件重开保持路径，普通保存无需重新命名。

## 实施裁定

1. 复用现有 `codex/phase2-foundation` 工作目录，因为功能依赖已有未提交的草图保存与工程图模板工作；保存了起始差异，未重置、提交或推送用户文件。
2. 桌面入口启用 `DocumentSession`；不传会话的 `MainWindow` 保留旧单文档嵌入接口。代价是两条生命周期路径仍需维护。
3. 迁移生成连续的本地序号，完整原档及原审计六字段保留于 `migration_origin`。代价是文件增大。
4. 相对来源位置存于 v4 `reference_locations`，不改写原命令参数或自动采用新几何；来源不在会话中时，另存也从原目录重算路径。
5. 不同路径另存生成新文件身份，成功后替换当前条目，独占复用其未改变的内核；不产生两个共用内核的可编辑条目。同一规范路径另存按普通保存处理，保持身份。
6. 桌面 CLI 的 new/open/save 转向文件菜单，防止绕开多文档路径与内核管理；独立 CLI 保留原行为。
7. 草图分离创建独立副本，保留原内部草图及建模消费者，避免改变已有模型的可重放历史；关联草图须先解除关联。
8. 原命令目录夹具已遗漏此前发布的 drawing.note；新增 reference 命令时同步补齐明确清单、CLI 数量及 DTO 影响类型，没有放宽断言。补上原来遗漏的 `drawing_note` Literal。
