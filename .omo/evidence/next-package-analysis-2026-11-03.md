# 下一包源码分析：球体补齐 → M2-B 独立零件草图

日期：2026-11-03。状态：源码核对与范围建议，未修改产品代码，不是已批准的实施设计。

用户已确认本次孔轴世界原点捕捉修复测试通过。M2-A 既有分区全量证据与之后的定向修复证据分别保留，不用本次反馈代替所有基准交互的逐项验收。

## 1. 推荐次序

球体基本元素补齐包 → M2-B 独立平面草图工作台 → E3-B 绑定孔 GUI。

依据：M2-A 实施计划的用户补充部分已记录“验收取点后补齐球体，再继续 M2-B”。球体不是草图的技术依赖，但属于明确提出、尚未交付的功能；先完成一个较小 GUI 闭环，避免遗漏。M2-B 主线保持不变。

路线比较：直接进入 M2-B 可以更早推进草图，但会继续积压球体；把球体混入 M2-B 会扩大同一包的验证面。推荐独立补齐球体后开发 M2-B。此为分析建议，不冒充用户已批准新设计。

## 2. 球体包的真实改动面

| 源码 | 当前事实 | 必须处理 |
| --- | --- | --- |
| `builtin_commands/specs.py` | 基本体仅 box/cylinder | 注册 sphere、参数和 CLI 别名，走既有 schema/Bus |
| `geom/_b123_ops.py` | 参数 union、构造、分派只含 box/cylinder | 半径和球心防御校验；球体构造；复用布尔和结果校验 |
| `geom/kernel.py` | 基本体分支、单实体校验名单只含 box/cylinder | 扩充分派、快照、来源和拓扑演化；覆盖隔离重放 |
| `geom/design_faces.py::_seed` | 非 box 直接按 cylinder 取 height、建立上下平面角色 | 显式限定支持类型，球体不生成虚假的平面角色；不能仅扩 kernel 名单 |
| `ui/main_window.py` / `modeling_toolbar.py` | 工具入口、定位、参数、标签均枚举命令 | 接入球体命令条和实时预览；明确球心输入及确认/取消 |
| `tests/geom/test_kernel_primitives.py` | sphere 是未实现命令拒绝样例 | 改为真实球体验证；保留其他未知命令拒绝测试 |

建议命令：`feature.sphere@1(radius, center=[0,0,0], mode=new|add|cut)`；长度 mm，半径必须正且有限，球心三个有限数值。球体无需方向参数，不增加半球/角度截断参数。

现有 `new` 的语义是替换当前实体结果，`add` 合并，`cut` 切除；不能将本包的 new 偷改为新增独立实体。GUI 必须清楚说明替换行为。空模型允许 new/add，cut 按既有规则拒绝。新建球体不凭空产生可供平面草图或平面孔绑定的球面“主平面”。

球心建议支持数值 XYZ、世界原点和精确对象锚点一次定位；任意离面 XYZ 不能默默压到 XY。若采用锁定平面定位，应明确平面和 UV；数值不再吸附，Shift 绕过，隐藏/过期对象不参与。复用 M2-A 的中立定位服务，避免第三套坐标解释。

完整球体中心建议作为本包明确验收的捕捉锚点，由几何端口给出，不能依赖球面缝线恰好是圆边，也不能用布尔后的实体质心冒充原球心。裁切后的球面中心捕捉需要明确按解析球面提供或暂不支持，不以错误坐标兜底。

复用现有档案版本策略；仅增加基本体不应无条件升级 v6。新命令在当前程序中可保存重放，不承诺旧程序认识新增命令。修改既有文档后仍保持审计、redo、失败恢复及保存行为。内联布尔工具目前仅 box/cylinder；本包先交付球体的 new/add/cut，不将内联工具支持冒充已完成。

### 球体 GUI 与数据验收

1. 空零件创建 R=10、球心 (0,0,0)，预览可旋转；确认后体积为 `4πR³/3`，包围盒尺寸 20×20×20，球心准确。
2. 任意 XYZ 球心、原点/实体特征点捕捉、数值精确输入、Shift、不同视角和隐藏对象规则一致；完整球体中心可捕捉。
3. 已有实体下 new/add/cut 各自符合契约；相交、相离、完全切空按既有规则处理，几何失败不能破坏原模型。
4. 改半径连续预览只允许最新结果确认；取消及失败不修改档案、历史、redo、dirty 和模型。
5. 确认后撤销/重做、历史改参、保存重开、STEP/STL 导出；对受支持来源平面的绑定引用，检查布尔后的正确保留或明确失效。
6. 验证命令/schema、实际几何、候选与持久化、Qt 工作流和人工桌面操作。按路径跑四门，最终集成一次全量；不把创建截图当作全部通过。

## 3. M2-B 已具备和仍缺失的部分

已有：WorkPlaneFrame、UV/世界转换、精确锚点、射线平面求交、候选 scene/generation、datum 草图支撑、二维实体/编辑算法/约束端口、草图拉伸消费者。可复用算法与端口，不能复用二维工作台可变会话。

| 缺口 | 证据 | M2-B 必须交付 |
| --- | --- | --- |
| 三维入口仍构造二维编辑器 | `MainWindow._on_sketch_start`、`_show_sketch_workbench` | 独立 PartSketchWorkbench/会话/工具栏，留在原零件 GL 场景 |
| 新基准支撑未接入草图入口 | 入口仍读普通选面并生成 SketchSupportFace | 显式选基准、锁平面，保存既有 support 引用与局部放置 |
| 相机保存不完整 | `GLViewport.camera_state()` 只有 distance/center | 保存并恢复方向姿态及实际使用的投影状态；正视/自由旋转不改工作平面 |
| 草图显示不等于可编辑 | `_sync_sketch_items` 是显示入口；编辑交互在二维 canvas | 3D 场景中的实体/端点命中、选择、拖动、删除和尺寸标注交互 |
| 草稿交互与求解仍耦合旧窗口 | `SketchEditorDialog` 包含绘图/捕捉/尺寸/undo | 独立草稿和局部撤销，复用纯算法与求解端口；失败保留可修正草稿 |
| 模型面绑定不是既有 datum 支撑的同义词 | `spatial_datums.associated_frame` 只接受 datum_plane | 固定主平面、datum 关联、旧 support_face 兼容分别说明；新持久绑定面需要契约扩展，不能声称自动具备 |
| 候选内新增身份仍不稳定 | `ReplayAppend` 无局部身份；Bus 每次准备生成 instance_id | 继续分别确认平面、草图、拉伸；不得在下一次 stage 沿用上次新对象的命令身份 |

### 建议的 M2-B 范围与闭环

- 空零件或已有零件选择固定主平面/已有基准，锁定后原位绘制；支持模型平面时必须明确旧查询语义和真正持久绑定的区别。datum 可画出显示矩形边界，平面草图不应被有限面轮廓截断。
- 首个闭环包含线段/连续线、矩形、圆/圆弧，以及选择、端点修改、删除、局部 undo/redo。更复杂二维工具需逐项排期，不自动复制图层、纸张和排版功能。
- 驱动长度、距离、角度、半径/直径和适用几何约束；显示欠约束/冲突/无解状态，只在求解结果有效时确认对应变更。纯显示尺寸不能冒充驱动约束。
- 对象捕捉、栅格显示、栅格吸附独立；复用世界/用户坐标系原点与精确端点/中点/圆心。离面点拒绝或显式投影；重叠候选有明确切换反馈；数值不再次吸附。
- 显示、命中、捕捉和求解结果绑定同一文档/候选 generation；视线近平行时禁止不确定鼠标落点，数值输入仍可操作。
- 确认草图后独立启动拉伸；编辑已有草图需完整预演下游拉伸，失败时保留源模型和草稿。草稿内撤销与已提交历史撤销分别说明，不承诺目前没有的修订级 undo。
- 取消、切文档、关闭、保存期间的草稿处置和晚到回调都纳入会话生命周期；第一次使用关联支撑的 v6 升级仍在候选中准备，确认走原 Bus。

GUI 验收主链：空零件建偏置基准 → 进入独立草图 → 原点捕捉画闭合轮廓 → 驱动尺寸 → 旋转检查/正视 → 确认 → 拉伸 → 重开并编辑尺寸 → 下游重建。补充冲突、取消、过期、近平行视线、隐藏父基准、多文档和保存重开的反例。

非共面 XYZ 空间草图仍属 M5；角度/三点基准与多坐标系完整管理属 M3。新绑定面能力按既有 M4/E3-B 边界单独核定。M2-B 完成不得覆盖这些待办。
