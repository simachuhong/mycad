# P2-09｜端到端性能基准与预算

## 方法与环境

可重复命令：

```bash
uv run python scripts/benchmark_phase2.py \
  --sizes 10 25 50 100 --samples 30 \
  --output .omo/evidence/p2-09-reference-benchmarks.json
```

每种特征数量在独立子进程中运行，底板为 180×120×10 mm；逐条添加半径 2 mm、高 20 mm 的圆柱切除，
网格为 11 列。10/25/50 特征的行距为 20 mm，100 特征行距为 10 mm 以适配底板。
打开、单步撤销/重做、热缓存读取、offscreen 场景刷新和数学射线拾取各采 30 次；建模命令的单条
耗时样本数等于特征数量；每种冷网格/冷历史/细容差各测 1 次。百分位使用 nearest-rank，
少于 30 个样本的 P95 标为 `small_sample`，不能视为稳定尾延迟。

参考机：Intel Core i7-7500U @ 2.70 GHz、4 个逻辑 CPU、Linux 7.0.0-38-generic、x86_64、
Python 3.12.3、build123d 0.11.1、cadquery-ocp-novtk 7.9.3.1.1、PySide6 6.12.0、
pyqtgraph 0.13.7。采样时间：2026-10-24 07:12 UTC。GUI 指标使用 Qt offscreen；不含真实窗口绘制、
GPU 帧时间或屏幕合成。RSS 是每个隔离子进程的 high-water RSS，包含 Python、Qt 和 OCCT 原生分配。

## 预算与判断

- 拾取 P95 锁为 **<100 ms**；最大规模基线为 22.049 ms。
- 场景刷新 P95 上限为基线的 1.25 倍并向上取整至 5 ms：10/25/50/100 特征分别为
  **20/30/65/125 ms**。
- 打开/撤销/重做 P95 上限为相应基线的 1.25 倍并向上取整至 1 ms。100 特征预算分别为
  **5,465/5,019/5,386 ms**；其他规模以表中基线同法计算。
- 单条建模命令 P95 上限为同规模基线的 1.25 倍并向上取整至 5 ms：10/25/50/100 特征分别为
  **20/30/50/90 ms**。10 与 25 特征的样本不足 30，只作为预备预算，后续回归报告须增加重复建模样本。
- 峰值 RSS 硬上限锁为 **1,024 MiB**；100 特征参考观测为 832.6 MiB。
- 25 特征时打开、撤销、重做 P95 已超过 200 ms；冷网格从 25 特征起也超过 200 ms。
  100 特征任务中点历史态（ordinal 49）冷网格生成约 386 ms。因此 P2-10 对 GUI 命令执行、打开、撤销/重做、几何预热及显式历史预览采用串行 worker。
