# U13 尺寸、缩放与集成证据

2026-11-05 在 Linux x86_64、Python 3.12.3、PySide6/Qt 6.12.0、Xvfb/xcb 和软件 OpenGL 下，分别以 1024×768、1366×768、1920×1080 的虚拟物理屏幕及 100%、125%、150%、200% 缩放采集 12 组，每组含首页、零件、零件草图、绑定孔、历史编辑、历史参数弹窗、独立二维、工程图，共 96 张。每组 JSON 记录实际逻辑窗口/屏幕尺寸、DPR、关键入口可达性和部分可见裁剪尺寸；[采集脚本及各组记录](u13-matrix/) 可复现。

当前脚本检查的窗口尺寸均未超过可用逻辑屏幕；首页三入口、文档标签、草图平面/绘图/完成/动态输入、绑定孔确认/取消/可滚动预览、历史参数/确认/取消、二维命令输入、工程图来源入口均可到达。脚本还检查草图及绑定孔视口至少 250×80 逻辑像素、二维画布至少 60 逻辑像素高及命令输入至少 25 逻辑像素高。初次检查发现 1024×768/200% 下最小窗口超屏、控件挤压；现已调整小屏窗口、图标工具条、可展开功能区及面板临时收起，并加入面板偏好恢复测试。扩展草图后矩阵发现 1366×768/150% 下绑定孔视口过矮，调整阈值并重采受影响组合后，12 组、96 个画面的上述检查均通过。

以上是自动可达性检查与程序截图，不涵盖所有交互、显示器缩放设置或用户视觉判断；并非 ST10/AutoCAD 的行为对照，也不能证明 Windows、真实输入法、焦点或用户验收通过。U13 不勾选，完整全量四门尚待所有开发范围及验收前置条件具备后执行。

补充：零件草图在 512×384 逻辑窗口中另行验证。保存的草图布局可能重新显示面板并压缩画布，展开的草图工具也可能挤占画布；现在恢复布局时保留临时收起策略，草图工具区在小屏可滚动且限制高度。回归测试检查已保存面板布局、画布可见面积、平面与绘图等控件的滚动可达性及取消后的功能区状态；这项测试不替代其余尺寸及真实交互验收。

200% 缩放草图专项曾出现窄屏动态输入被隐藏的回归：专项中 113 项通过、1 项失败；将工具区高度限制仅用于矮屏后，失败用例与极小屏用例复测均通过。后续矩阵发现 1366×768/150% 下绑定孔视口高度不足，现将矮屏阈值调整为 600 逻辑像素并针对受影响组合复测。受影响文件的 Ruff 和 basedpyright 检查通过。

跨环境 scoped 回归：启动页、动作目录、工作区标签、文档会话及保存、二维绘图验收、工程图视图/更新/标注/PDF、历史编辑和绑定孔共 196 项通过（xcb 软件渲染）。此组开始后又增加基准编辑，其新增路径以 U11 专项测试单独验证。

配置隔离例外：一份临时小屏诊断脚本误用了默认 MyCAD QSettings，可能更改本机零件及零件草图布局偏好；未捕获准确原值，未用旧备份覆盖。矩阵脚本和 pytest 使用临时配置目录。事件已记录至 `.omo/start-work/ledger.jsonl`。
