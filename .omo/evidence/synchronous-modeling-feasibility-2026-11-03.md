# 后续同步建模可行性评估

日期：2026-11-03。性质：基于当前源码、已安装依赖和官方文档的评估；不是已批准实施设计，也不是几何算法原型验收。

## 判断

可以在后续阶段逐步增加直接编辑和有限同步能力，不必推翻现有 M2-B、Bus 或全部改用另一种内核。但达到 Solid Edge 同步建模的覆盖面，需要独立、持续的几何研发项目，不能按几个推拉按钮估算。推荐保留历史建模主线，先做受限直接编辑，再做三维约束与设计意图传播，最后评估混合建模分区。

评估区分三层：

| 目标 | 实际含义 | 当前可行性判断 |
|---|---|---|
| 原位参数编辑 | 拖动拉伸高度、修改盒体尺寸或孔径，底层修改已有特征参数 | 较高，可复用候选预演；属于更便捷的历史参数编辑 |
| 受限直接编辑 | 在当前实体上移动/偏置选定面，删除并修补指定特征，不要求先找原草图 | 有条件可行；需要局部 BREP 重建和持久面引用；先限解析曲面及受控邻接 |
| 同步建模 | 直接修改实体，同时维护选定的三维尺寸、共面/平行/同轴/对称等关系，并处理关系传播与冲突 | 有研究可行性，工程风险高；现有二维求解器和几何 API 不构成完整方案 |

Siemens 将同步建模描述为直接操作和参数控制的结合，并支持与顺序特征共同使用；设计意图识别还涉及面关系及用户选择保留/忽略哪些规则。[官方混合建模说明](https://blogs.sw.siemens.com/solidedge/hybrid-modeling-in-solid-edge-with-syncronous-and-ordered-modes/)、[官方设计意图说明](https://solidedge.siemens.com/en/resource/video/design-intent-recognition/)。本评估只提出 MyCAD 的可实现子集，不声称兼容或复刻其全部行为。

## 当前资产与缺口

| 核查对象 | 已有资产 | 对同步建模的限制 |
|---|---|---|
| `core/bus.py`、ADR-001、`app.py::ReplayCandidateSession` | 唯一写入、审计、隔离候选、提交前检查和失败回滚 | 直接编辑需设计新命令参数和版本；拖动过程不宜每个鼠标事件全量重放 |
| `core/bound_refs.py` | 命令实例身份 + 面角色 | 当前仅盒体六面、圆柱上下端面；不是通用实体面身份 |
| `geom/design_faces.py` | 保守追踪部分布尔操作后的平面血缘 | `_advance` 会将法向或平面位置变化判为 drift；split/merged 等不自动续接；支持操作列表有限 |
| `core/topology_evolution.py`、`geom/topology_evolution.py` | preserved/modified/generated/split/merged/deleted/unknown 词汇及布尔演化证据 | 索引只在一次操作内有效；不能拿来直接持久化，也不是面编辑的完备命名算法 |
| `core/semantic_refs.py` | 运行期面/边选择及代次校验 | 包含 runtime feature/topology identity，不等同于跨重开持久引用 |
| `geom/sketch_constraints.py` | PlaneGCS 二维草图、约束诊断及冻结结果 | 没有通用实体三维约束图、面参数求解和实体重建能力 |
| `geom/kernel.py::_regenerate_with_sketches` | 当前接受草图状态驱动下游重建 | 新增实体直接编辑必须参与重建、重新定位面，并防止旧编辑结果覆盖新的上游意图 |
| `formats/providers/step_provider.py` | STEP 导出 | `can_read=False`；导入实体编辑需额外建设产品级导入、来源存储、基体身份及重放能力 |
| `ui/execution.py` | 串行几何工作线程，晚到结果管理可沿用现有机制 | 运行中的 OCCT 不被强行中断；需合并拖动请求，限制过期任务占用 |

特别注意：现有引用保守拒绝漂移是保护既有命令的规则。未来应增加可跟随编辑的引用语义/新版本，不能直接删除 drift 检查，让旧绑定孔或草图悄悄改变行为。

## OCCT 是否足够作为起点

本地只读检查确认当前环境为 `build123d==0.11.1`、`cadquery-ocp-novtk==7.9.3.1.1`、`planegcs==0.9.6`；OCP 可导入 `BRepAlgoAPI_Defeaturing`、`BRepOffsetAPI_MakeOffsetShape`、`BRepTools_ReShape`。这只证明接口存在，不证明任意面编辑可行或可靠。

- OCCT 7.9.3 的 Defeaturing 提供指定面集的特征移除，支持实体输入并可记录形状变化。[对应版本源码说明](https://github.com/Open-Cascade-SAS/OCCT/blob/V7_9_3/src/BRepAlgoAPI/BRepAlgoAPI_Defeaturing.hxx)
- ReShape 提供预定义子形状替换；调用替换不能代替邻接面的延伸、重新求交、修剪和闭合实体检查。[对应版本源码说明](https://github.com/Open-Cascade-SAS/OCCT/blob/V7_9_3/src/BRepTools/BRepTools_ReShape.hxx)
- Offset API 对曲面连续性、自交及复杂顶点有明确限制；其自交消除选项未实现。形状偏置不等同于通用单面推拉。[对应版本源码说明](https://github.com/Open-Cascade-SAS/OCCT/blob/V7_9_3/src/BRepOffsetAPI/BRepOffsetAPI_MakeOffsetShape.hxx)

据此推断：OCCT 可作为受限直接编辑的算法基础，现阶段没有证据要求换内核；但“替换一个面再 sew”不足以形成工业级直接编辑。复杂倒圆、薄壁、面消失、合并分裂和曲面相切传播需要专项算法与样本验证。

## 与历史、撤销和存档的关系

**交互不依赖原草图，不等于系统不能保存操作日志。** 首阶段可把直接编辑作为历史中的新操作，输入为当前可重建实体、稳定目标引用、编辑值和已接受规则；依然由 Bus 提交和重放。不要保存屏幕拖动轨迹或原生 Shape 指针。

例如：原草图拉伸 10 mm，再向外偏移顶面 2 mm。以后把原拉伸改为 20 mm：若第二步定义为相对偏移，结果应为 22 mm；若用户设置的是最终总高 12 mm 的驱动尺寸，则必须按绝对约束重新求解，可能产生冲突。两种命令不能共用含糊的“面移动到这里”语义。

持久三维关系、临时推断关系、只读测量必须分开。持久规则在之后的相关编辑中必须继续生效；重放不能使用最新版启发式重新猜用户意图。冻结被接受的关系集合、作用对象、求解分支、算法版本及必要的解数据；未来显式重新识别/求解属于新操作。

原始草图尺寸继续控制其顺序特征；实体直接编辑默认改变该步骤之后的实体，不自动反写草图。两者冲突时显示影响并要求选择，而不是由最后一次鼠标动作静默改另一端。未来转换为同步基体必须显式，并说明原特征/尺寸是否继续驱动。

若进一步实现独立同步实体状态/关系图，再由顺序特征依赖它，应单独设计求值边界和 ADR。保留命令事件仍有可能，但不能声称当前线性特征重放已自动支持任意双向依赖。禁止循环依赖。

持久化不必一开始就存完整 BREP，但导入基体必须可自包含或可靠重取，单存本机路径不可接受。大模型缓存、冻结 BREP、求解版本兼容和格式迁移分别设计；现有档案已经演进到 v6，不能沿用旧 ADR 中“未来 v2”的字样直接占用已发布版本。缓存是可废弃加速数据还是权威基体，也必须明确。

## 推荐阶段与退出条件

| 阶段（评估代号，不改现有 M 编号） | 范围 | 进入下一阶段的证据 |
|---|---|---|
| S0：技术验证 | 简单平面移动、圆柱面半径编辑、删孔修补；先用受控原生实体 | 正负编辑、邻接变化、失败回滚、有效闭合实体、体积与拓扑变化正确；不是只看截图 |
| S1：有限直接编辑产品化 | 明确支持域、面选择/操纵器、独立预演、提交/撤销/重开；初期操作主要追加到模型末尾 | 稳定引用可重放；改上游后能正确重应用或准确报告失效；复杂不支持输入明确拒绝 |
| S2：有限同步约束 | 先显式固定/共面/平行/同轴、距离/半径；再逐步引入可见且可关闭的关系识别 | 编辑传播正确、冲突对象可定位、既有关系持续有效、分支选择可解释、无隐式改写草图 |
| S3：混合建模 | 同步基体 + 顺序下游；产品级导入实体、缓存和迁移；按需求扩面类型 | 跨边界编辑、复杂后续特征重建、导入重开与版本兼容测试，以及性能样本集 |

M2-B 与关联编辑/失效闭环（M4）对这条路线的帮助，比先完成全部空间曲线工具更直接。S0 可以在这些基础趋稳后单独立项，不必机械等全部 M5/M6 结束；但不能把 S0 加入当前 M2-B 的交付范围。

首批样本建议覆盖：方块/台阶、带通孔与盲孔的板、同轴圆柱、简单薄壁、带圆角邻接、对称重复面、面分裂合并和意外删面。对每例验证实体有效性、目标尺寸、未选区域变化、身份/关系、撤销重放及旧存档；记录鼠标反馈与精确候选耗时。未跑样本前不给成功率和交互帧率承诺。

投入判断：S0 是有界研究任务；S1 是跨 core/geom/UI/档案的独立功能包；S2/S3 是持续研发。当前没有直接编辑样本和基准数据，无法可靠给出人月或交期，先以 S0 结果估算，而非根据 API 数量报价。

## M2-B 当前只需保留的边界

1. 草图、实体、特征命令、尺寸与运行期拾取身份分离；不假定所有未来尺寸都属于草图。
2. 接口区分“编辑原特征参数”和“编辑当前实体”；UI 不绕过中立命令/候选服务直接操作 OCCT。
3. 保留稳定实体/草图 ID、候选 generation、错误定位、取消和原子提交，不将短期 topology ID 写入档案。
4. 完整求值及重建留在服务层，工作台只消费结果；避免把求解策略、约束迁移和身份修复写进事件处理器。
5. 先补齐 M2-B 复审的草图修订与约束提交契约。这对顺序草图本身就必要，不需要为未来同步建模提前发明通用求解系统。

本次没有修改产品代码、依赖或现有批准设计，没有开发几何原型；只做了源码/文档核查和本地 API 可用性检查。全文路线为建议，需在相应阶段独立设计与验收。
