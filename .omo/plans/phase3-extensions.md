## 架构与数据边界

长期沿用 Phase 2 分层、唯一 Bus 写入、确定性重放、命令版本和审计不变量。
网络/数据库驱动、SQL、Qt、厂商 SDK 均不进入 core；数据库事务与 CAD Bus 事务是不同边界。
本阶段新接口需要单独的版本与迁移决策；不能直接给 v1 metadata 添加未允许字段。

| 数据/动作 | 权威或处理位置 | 边界 |
| --- | --- | --- |
| 设计几何与历史 | native 文件 + CAD 重放 | DB 索引、缓存、企业状态不能旁路改写 Document |
| 项目索引、设计版本索引、外部对象关联、交付回执 | MyCAD 自有数据库 schema | 用源文档 ID/版本/摘要绑定，可核对；不读取或写入厂商私有业务表替代 API |
| 物料/业务修订/生命周期 | 企业指定 PLM | DB 中只保存关联与带来源/时间的缓存 |
| 工艺路线、工序与反馈 | CAPP | 反馈影响几何时生成新的受确认计划 |
| 文件历史/分支 | Git | commit 不等于业务发布；数据库不替代 Git |
| 编码 | 唯一企业编码权威 | DB 唯一约束可辅助本地索引，但不凭空取得正式料号分配权 |
| 网络调用/同步/编号/Git push | 独立基础设施或集成服务 | 不放进建模命令重放；undo/redo/open 不重复外部副作用 |

无 AI、企业或数据库连接时基础手工 CAD 仍可离线使用。数据写入/发布按用户明确动作发生，
连接测试只检验可达性、权限和版本，不建库、不迁移、不上传设计。

## AI Provider / Models 产品架构

Provider 是服务连接实例，Model 是该实例内可调用的具体模型，二者均不等于 CAD Agent。
建议保留统一模型服务端口，以协议适配器实现不同 API；原 ADR-004 的 OpenAI 兼容路线作为
首批适配方式。加入其他原生协议前形成 ADR 增补，不能将“兼容”解释为功能与参数完全相同。

| 模块 | 责任与关键数据 |
| --- | --- |
| ProviderRegistry | 实例 ID、显示名、协议、base URL、region/workspace、credential_ref、超时/代理、启用状态；允许同厂商多个账号/地域实例 |
| ModelRegistry | `(provider_instance_id, model_id)` 身份、显示名、可用性、上下文/输出限制、能力状态、来源与探测时间；自动发现和手动添加并存 |
| ProviderAdapter | 连接检测、可选模型发现、请求/流事件/错误归一化、取消；不持有 Document 或调用 Bus |
| 任务配置 | 对话、建模计划、解释/修复等角色选择模型和参数；先支持单模型默认，再允许按任务覆盖 |
| 设置界面 | 服务连接 → 模型发现/添加 → 能力验证 → 默认任务模型；区分连接成功、模型可调用和 CAD 任务达标 |
| CAD Agent | 提取受控设计上下文 → 声明式计划 → schema/单位/引用/几何检查 → 用户确认 → Bus → 结果检查 |

能力以“支持/不支持/未知 + 来源”管理，至少区分文本、流式、视觉、tool calling、JSON object、
JSON Schema、上下文窗口和模型特定参数。服务列出某模型，不保证当前凭据有调用权限，
也不保证它在该 endpoint/protocol 下支持所有声明能力。格式合法不等于几何正确。

首批以 DeepSeek/通义兼容服务和 Ollama 本地路线建立契约样本，具体模型不硬编码在 UI。
本地建模继续可离线；网络/SDK 仅存在于 Agent 基础设施适配层，GUI 只使用设置服务。
凭据保存在操作系统凭据存储或显式环境配置中，配置保存引用，日志与 `.mc.json` 不保存密钥。
模型调用优先发送任务所需的尺寸、单位、选择引用和命令能力；原始模型、图纸图片和完整历史的发送
应有明确的数据范围与用户可见设置。按任务冻结 provider/model/config，失败不得静默切换外部服务。

### 更适合 MyCAD 的 AI 入口

建议按风险与可验证程度组织，而不是将所有行为都放进一个开放聊天框：

1. **解释当前对象/操作**：使用选择、单位和已知参数；不修改模型。
2. **修改一个明确参数**：例如厚度 8 → 10 mm，展示变化与保持项，生成可编辑计划，
   经原确认/修订绑定机制执行；定位不唯一时澄清。
3. **生成受约束的代表零件方案**：先以安装板、法兰的已验收命令组合为样本；
   可在 P2-19/P3-21 的评测中使用，不必先开发独立模板市场。
4. 自由多步生成、任意面推拉、自动修复任意失败模型留到具体能力与评测通过后开放；
   AI 配置可先交付，开放改模仍遵守 Phase 2 Gate C 与本阶段 Gate D，不绕开原阶段门。

手工参数编辑、AI 参数修改和未来参数拖柄应通向同一规范化命令、预览及检查服务。
Provider 负责连接和能力，Agent 负责生成计划，Bus 负责写入；模型服务不成为第二个几何引擎。

### 当前源码约束

- schema_v1.py 的 metadata 仅接受 part_no、revision、material、source、part_name、notes；
  未知字段会被拒绝，不能直接追加 PLM ID、项目、状态或任意企业属性。
- ExecutedCommand.id 表示命令类型，ordinal 表示历史位置；两者不能直接作为跨分支、
  跨企业系统的永久对象/命令实例身份。与 P2-11 的特征/实体身份设计一起处理。
- 现有插件主要贡献命令和格式，Python 插件是完全信任代码；
  “装一个插件”不等于已经具备企业权限、生命周期、远程事务或审计保障。
- 本轮不修改 v1、命令审计字段或现行 ADR。新企业信息的持久化在 P2-24 基础 CAD 格式之上，由 P3-45
  比较新版格式与项目清单/旁车方案，解决复制、重命名、分叉及丢失旁车的问题再定版。

### 必须分开的身份、版本与数据归属

| 概念 | 建议契约 | 不应混用 |
| --- | --- | --- |
| 设计文档/特征身份 | 内部不可变 ID；复制、另存、分支、派生分别定义保留/新建规则 | 文件路径、显示名称、历史 ordinal |
| 企业物料/零件编码 | 由指定编码权威发放或验证，记录命名空间与规则版本 | 内部 UUID、文件名、AI 自拟字符串 |
| PLM 主对象与版本对象 | 保存系统实例、对象类型、外部 ID、业务修订、迭代/版本令牌 | 仅一个 URL，或只保存可能重复的料号 |
| 本地编辑修订 | 单调变化，用于并发检查与计划失效 | 可回退的历史长度、业务修订 A/B |
| Git 提交 | 精确项目文件快照及父提交关系 | PLM 发布状态、业务修订号、用户审批 |
| 文件摘要 | 绑定交付文件字节与清单，显式算法/生成版本 | 绝对几何等价证明或稳定对象身份 |
| CAD 文档与企业 Item | 显式关联角色，可按适配器处理一对多/多表示 | 默认“一份文件就是一个物料” |
| 工艺对象/版本 | CAPP 管理路线、工序及其版本；关联源设计版本和目标特征 | CAD 特征树、命令历史或 EBOM |

建议权威归属：MyCAD 管设计内容与建模历史；PLM 管受控物料、业务修订及生命周期；
CAPP 管工艺路线与工序；Git 管项目文件版本；编码规则由企业指定的一处权威维护。
允许企业没有某个系统，但不能让多个系统无规则地同时改写同一个权威字段。
外部状态缓存必须记录来源、版本令牌与获取时间；离线时显示“状态未核实”。

这些边界与企业系统的实际对象模型相符：Windchill 将 CAD 文档作为受修订和生命周期管理的对象，
并区分 CAD 文档与 Part 的关联；Siemens 的制造规划资料区分 MBOM 与 BOP。
它们仅作为契约设计依据，不代表已适配具体版本。
[PTC CAD 文档域](https://support.ptc.com/help/windchill_rest_services/r2.2/en/windchill_rest_services/CADdocumentmgmtdomain.html)，
[Siemens 制造规划](https://blogs.sw.siemens.com/teamcenter-manufacturing/2026/07/28/whats-new-in-teamcenter-manufacturing-easy-plan-2606/)。

### 四类接口的最低契约

下表方法名仅描述语义，不注册命令 ID、不创建实际 SDK 或运行端点。
接口使用版本化中立 DTO；厂商字段、协议和认证放在适配器，不进入几何核心。

| 端口 | 输入/输出与应预留操作 | 失败/范围边界 |
| --- | --- | --- |
| PlmPort | 查询关联/元数据/能力，读取生命周期与版本令牌，准备交付包，显式发布并返回回执；变更单保留引用 | 权限不足、版本冲突、已发布只读、部分成功和远端状态未知必须区分；本轮不做审批工作流引擎 |
| CappPort | 输出受控设计快照、单位/坐标系、材料引用、已知几何特征及证据；接收关联到具体设计版本的工艺反馈引用 | 不从普通圆孔直接推断完整加工路线；未知公差/粗糙度保持未知；不承诺完整 PMI、工艺自动生成或 MES |
| ScmPort | 项目状态、历史/差异、显式提交、分支与恢复的能力描述；远端 fetch/push 与本地动作分开 | 指 CAD 项目文件的 Git，不是 MyCAD 软件源码仓库；缺少 Git/远端时本地建模仍可用 |
| NumberingPort | 规则校验、编码预览、申请/预占、确认/释放、已有编码查询；返回规则版本及权威来源 | 预览不等于取得编码；并发唯一性由分配权威保证；离线只能用明确的临时标识，AI 不分配正式料号 |

共同字段建议包含：接口版本、企业/项目上下文、请求 ID、操作 ID、目标文档/快照、
预期本地与远端版本、幂等键、能力集合、结构化错误和脱敏的来源/审计信息。
认证材料使用引用，未来适配企业 SSO/服务账号；不得进入 native 文件、Git 或交换包。

编码规则的首个契约覆盖前缀/分类/流水号/校验规则及规则版本，不建设可视化规则编程平台。
旧编码不因规则升级自动重新编号；重编号需显式业务操作并保留关联。
材料显示文本与受控材料字典 ID 分开，图号、零件号和文档号是否相同由企业规则映射。

### 交付包、发布与重放隔离

建议以“冻结快照 → 生成并检查交付清单 → 明确发布 → 记录外部回执”作为集成边界。
清单至少描述：设计身份/业务关联、精确源版本、文件名/类型/单位/摘要、生成器版本、
受支持的检查结果、依赖清单，以及可选 Git 提交和外部对象版本。
当前模型改动后，旧交付包与回执保留原版本语义，不能自动显示为当前模型已同步。

STEP/STL/DXF 等输出与 native 源文件必须对应同一冻结快照；版本不齐时拒绝作为一致包提交。
旁车/项目清单如被选用，应有内容绑定、缺失/过期检测和整体复制规则；
不能随意增加一个 JSON 文件然后假定它永远与模型同步。

外部发布、编码申请、Git push 不进入可重放的几何命令历史。
几何提交成功后才由集成服务处理明确的外部动作；undo/redo、打开重放不能重复触发它们。
跨本地和远端不宣称原子事务：超时可能已被接收，须查询回执/核对版本；
服务不支持幂等时不能盲目自动重发。将“本地已保存、待同步、同步失败、状态未知”分开。

CAPP 反馈若要求改几何，先形成针对具体设计版本的新草稿，再经原校验/确认/Bus；
不允许外部系统直接改 Document。失效的面/边引用必须显式报错，不能自动指向相似拓扑。
CAD 特征树不是 EBOM；未来装配的物料、实例、数量、变型、有效性等另行设计，
本阶段不把多实体文档宣传为已具备 BOM/装配管理。

### Git 集成应达到的语义

1. 确定项目边界及跟踪清单：native 设计数据、必要项目清单/规则引用；缓存默认可重建。
   发布用 STEP/DXF 等派生文件是否入库由企业策略决定，记录生成版本与摘要。
2. 原始审计字段保持不变；差异视图可按类型化参数展示变化，不能为了“干净 diff”删除时间戳。
3. Git 文本合并成功不表示 CAD 语义合并成功；历史顺序、引用和参数可能冲突。
   首阶段契约以冲突检测、选取版本、显式重新应用修改为主，不承诺自动三方几何合并。
4. 恢复/切换后须先校验并重建候选文档，再原子切换；保存未提交修改的处理必须明确。
   建模撤销不是 Git reset，恢复文件也不直接提升/撤销 PLM 发布状态。
5. 大文件存储和锁作为适配能力，客户端/服务端支持需协商；Git LFS 锁不能等同于 PLM 审批权限。
   未接入对应能力时，不显示虚假的“已锁定”或“已发布”。

Git 官方允许通过 attributes 指定文本/二进制差异及合并驱动；
Git LFS 另有锁定 API。这些机制不能自行理解本项目的几何历史语义。
[Git attributes](https://git-scm.com/docs/gitattributes)，
[Git LFS locking API](https://github.com/git-lfs/git-lfs/blob/main/docs/api/locking.md)。

### 企业上下文与 UI 预留

默认工作台仍保持明亮、简洁。文档身份区预留项目、编码/名称、业务修订、

AI 可用 provider/model 及能外发的数据范围预留项目策略输入；用户交互确认与企业授权分别检查。
单纯拥有可用 API Key 不等于有权上传企业图纸，发布确认也不等于企业审批完成。
本阶段只定义策略输入/结果与可见提示，不建设完整身份目录、权限管理或审计后台。

## 数据库接口与默认双库支持

### 范围与选型原则

MySQL、达梦是首批同等验收的两种默认后端，不把达梦留成“可扩展但未实现”。
它们是可选连接目标，桌面端不要求同时安装两库，也不默认安装/运行数据库服务器。
具体数据库大版本/补丁、驱动、Python、OS/架构、字符集与兼容模式由 P3-48 冻结并公开支持矩阵；
初期各锁定一组 Linux x86_64 的真实验证组合，不据此宣称全部版本、Windows 或信创架构已兼容。

建议采用“应用数据服务 → 按业务划分的 Repository/事务端口 → MySQL/达梦适配器”。
方法名在设计阶段仅表达语义；不提前注册命令 ID。UI 使用中立 DTO，不持有连接或拼接 SQL。
首轮估算按受控企业网、MyCAD 自有 schema 的适配部署计算；更大规模部署可将相同接口移至企业服务侧，
集中授权/API 网关/SSO 服务不在当前预算内。连接凭据不得成为跨企业项目授权的替代品。

MySQL 官方 Connector/Python 提供连接池与事务接口，可作为适配候选；驱动与许可/分发方式仍需选型确认。
[MySQL 连接池](https://dev.mysql.com/doc/connector-python/en/connector-python-connection-pooling.html)、
[事务接口](https://dev.mysql.com/doc/connector-python/en/connector-python-api-mysqlconnection-start-transaction.html)。
达梦官方说明 dmPython 遵循 Python DB API 2.0，且依赖 DPI 运行环境；因此应单列驱动、
运行库、Python/CPU 组合的安装与验证成本，不能按“SQL 兼容”推断即插即用。
[达梦 dmPython 官方说明](https://eco.dameng.com/document/dm/zh-cn/pm/dmpython-introduction.html)。
上述是选型依据，Repository 划分及交付边界是本项目建议；本轮没有做数据库连接或性能测试。

### 最低接口契约

| 端口/责任 | 首批操作与数据 | 验收边界 |
| --- | --- | --- |
| 连接配置与能力 | 类型、实例、地址/端口、库/schema、凭据引用、TLS/超时/池上限、只读状态、已验证版本 | 服务可达、认证通过、schema 就绪、读写权限分别报告；不回显密码/连接串 |
| Project/DesignIndex Repository | 项目、设计文档/版本索引、摘要、文件引用、分页查询 | 企业/项目上下文贯穿查询；缺失文件与过期索引可识别；不存一份可独立编辑的模型参数 |
| IntegrationLink/Receipt Repository | 外部系统实例/对象/版本、操作 ID、幂等键、交付清单摘要、回执及缓存时间 | 绑定具体快照；跨版本回执不误标当前模型已发布 |
| 事务工作单元 | begin/commit/rollback、预期版本、冲突/唯一约束/超时分类 | 原子性只覆盖当前数据库事务；提交状态未知要核对操作 ID，不能盲目重放写入 |
| Schema/迁移管理 | schema 版本、兼容检查、显式初始化/升级、备份/恢复说明 | 应用启动和连接测试不自动做破坏性 DDL；迁移有独立权限与失败恢复路径 |

主键使用应用生成的稳定 ID；设计版本、企业业务修订、DB 行并发版本分别表示。
需要唯一约束的字段定义企业/项目命名空间、大小写和空值规则，不能只在 UI 提前查重。
首批最小业务闭环：登记项目 → 索引已保存设计快照 → 保存外部关联/交付回执 →
按项目/设计版本查询 → 使用预期行版本更新 → 冲突或失败明确返回。
不建设通用报表平台、任意 SQL 控制台或全企业主数据管理后台。

### 双库差异、可靠性与运维

- 固定公共值类型及映射：稳定 ID、中文/Unicode、大小写、NULL/空字符串、布尔、DECIMAL、
  UTC 时间精度、字节摘要、JSON 文本/大字段。SQL 方言、分页、参数占位、upsert、DDL 放在适配层；
  不能假定 ORM 或某个兼容模式会消除数据库差异。序列/自增只作内部实现，不冒充设计身份。
- 数据库中不依赖厂商特有 JSON 查询维护核心语义；中立结构和 schema 版本可迁移，关键查询有明确索引。
- 连接池有容量/等待/超时边界；事务内不共享不安全连接，归还前清理会话状态，失败连接不继续复用。
  认证失败、库不存在、驱动缺失、权限不足、死锁/冲突、网络断开、提交结果未知分别提示。
- 文件保存与数据库写入不宣称跨资源原子：先形成已校验且可定位的文件快照，再登记索引/关联；
  DB 失败时本地保存仍如实成功，关联状态标为待登记/失败/未知。恢复后按操作 ID 和摘要核对再显式重试。
  必要的最小待办记录与恢复方案纳入 P3-51，不默认建设长期离线双向同步引擎。
- MySQL/达梦各自提供建库前提、最小权限、迁移版本、备份与恢复演练；分别验证安装许可及运行库分发条件。
  连接测试使用只读检查，schema 迁移与正常业务写入采用分开的权限/动作。
- 跨库切换需显式导出/导入和停写核对，不靠改一个连接类型就承诺数据迁移完成。
  首期验证中立导出/恢复样本；在线跨库切换、双写、集群高可用与自动灾备不作为首期承诺。

### 双库验收矩阵

MySQL 和达梦均跑同一套 Repository 契约及真实实例集成测试：中文及特殊字符、项目隔离、分页稳定性、
并发唯一约束、乐观锁冲突、事务回滚、连接池耗尽/失效连接、提交响应丢失、迁移中断、备份恢复、
文件摘要不匹配、旧回执/旧索引和断库继续手工建模。
DDL 失败恢复需各自验证，不假定两种库都支持事务性 DDL；无法原位回滚时走已演练的备份恢复。
报告锁定服务/驱动/系统版本，按已冻结的参考数据集记录查询延迟与资源，不编造百万级容量承诺。
没有真实达梦环境时任务保持未验收；mock、SQLite 或 MySQL 兼容模拟不能代替达梦证据。

  将可计划能力与影响对象描述归入注册契约，解决插件“可列出却不能进入计划”的边界，显式排除不可重放命令。
  验收：通过 P3-39～P3-43 的 provider/model 管理服务，至少一种已配置 provider
  完成意图—草稿—编辑—确认—执行—查询结果闭环；
  CLI 与卡片参数一致；超时/断网/非法输出/取消不改模型；失败信息可回灌，但修复后的新计划需重新确认；
  日志与存档不包含密钥，不把同进程 Python 插件的完全信任误描述为模型执行沙箱。

- [ ] **P3-22｜P1｜MCP 只读/计划工具和产品侧确认接入**

  依赖：P2-20、P3-21；面向用户改模受本阶段 Gate D 限制；准入评测在隔离环境先完成。
  入口：ADR-004、新增边界适配器、既有查询和计划服务。
  工作：实施前复核 MCP 官方规范与 SDK，固定实际验证版本，不能机械照搬旧 ADR 的版本预测；
  优先 stdio，工具提供命令发现、计划创建/校验、文档查询和导出 dry-run；
  执行入口验证产品侧凭据。客户端确认能力不足时回退产品 UI，不把客户端普通文本等同于授权。
  验收：工具 schema 与命令注册表同源；无凭据不能写入；显式计划句柄可定位且错误可诊断；
  跨客户端重放、过期计划、取消及重复请求受控；协议适配不成为 Bus 之外的写入路径。

- [ ] **P3-23｜P1｜Agent 任务级评测和执行准入门**

  依赖：P2-19、P2-20、P3-21；MCP 专项验收另依赖 P3-22。
  工作：评测从自然语言到规范化参数、几何有效性、关键尺寸、选择目标和用户任务结果；
  包含半径/直径、单位、角度方向、歧义引用、不可制造/不可建模参数、越界命令、过期计划和确认绕过请求。
  验收：声明式执行的确定性回归全过；未授权执行和静默错误目标的安全反例零通过；
  对模型生成成功率、澄清率、错误拒绝率、耗时/费用分别报告，记录 provider/model/config 和重复采样方法；
  先用基线确定生成质量阈值再锁定内测门槛，不将一次成功或 JSON 格式正确等同于完成设计任务。

  权限不足、旧版本回传、发布中改参、远端成功本地超时、缺失旁车均有时序与期望结果。
  不要求连接真实企业系统，不实施厂商 SDK、审批引擎、双向同步或自动工艺规划。

- [ ] **P3-47｜P1｜CAD 项目 Git 版本管理与语义差异契约**

### E. 数据库接口与默认双库实现

- [ ] **P3-48｜P1｜统一数据库接口、数据归属与双库基线**

  依赖：P3-00、P3-45、P2-24；关联/回执字段复用 P3-46/P3-47 的契约设计。
  工作：定版 Repository/事务/连接配置端口、最小自有 schema、项目权限上下文、行版本与幂等键；
  冻结 MySQL/达梦各一组版本、驱动、Python/OS/架构、字符集/排序/兼容模式及许可分发条件。
  比较 DB-API 适配与 ORM 方言的实测成本；不预先假定达梦等同 MySQL，不引入第三数据库主线。
  验收：中立 DTO、类型映射、失败语义、最小数据闭环、连接设置规格和测试矩阵可实施；
  数据库不接管设计历史，未知/缺失/过期索引可诊断；无数据库时 CAD 启动与离线流程不受影响。

- [ ] **P3-49｜P1｜MySQL 默认适配器与连接配置**

  依赖：P3-48。
  工作：实现参数化访问、稳定分页、类型映射、显式事务、乐观锁、唯一约束、连接池/超时/凭据引用；
  设置中可选 MySQL 并分别测试可达性、权限与 schema 状态，连接测试不产生业务或 DDL 写入。
  验收：锁定版本的真实 MySQL 实例通过最小业务闭环及 Repository 契约；连接断开、池耗尽、
  并发冲突、回滚、中文数据和日志脱敏通过；未安装/未启用驱动不阻塞基础桌面启动。
  迁移、备份恢复及跨资源故障另由 P3-51 联合验收，不以 SELECT 1 成功关闭本项。

- [ ] **P3-50｜P1｜达梦默认适配器与运行环境适配**

  依赖：P3-48；与 MySQL 使用同一 Repository 契约，独立实现方言和运行环境处理。
  工作：完成 dmPython 或经决策选定驱动及 DPI 运行库的安装探针、依赖隔离、连接设置与版本诊断；
  实测标识符/大小写、schema、空值/空字符串、中文、大字段/JSON、数值/时间精度、分页和事务映射。
  验收：真实达梦实例运行与 MySQL 等价的契约/业务样本，唯一性/并发冲突/回滚/断连行为符合中立定义；
  驱动或库缺失给出可操作错误，未启用时不阻塞 CAD；T2/国产 CPU 无实测不宣称支持。
  达梦与 MySQL 同等发布门槛，不接受兼容模拟或仅 mock 作为完成证据。

- [ ] **P3-51｜P1｜双库迁移、故障一致性与恢复验收**

  依赖：P3-49、P3-50、P2-24、P3-46 的冻结快照/回执契约。
  工作：实现显式初始化/升级、schema 版本检查、最小恢复/核对记录；分别制定备份恢复与权限说明；
  文件快照成功但 DB 失败、服务提交成功但响应丢失时，按摘要/操作 ID 核对并阻止重复写入。
  验收：两库均覆盖空库初始化、旧 schema 升级、迁移中断、非事务 DDL 恢复、断网/断库、
  乐观锁冲突、索引过期、凭据脱敏及项目隔离；备份实际恢复后能关联正确设计版本和回执。
  输出同一数据样本的中立导出/导入核对、性能基线、版本矩阵和未支持项；不承诺在线跨库切换或双写。
  关闭连接/取消等待与文档切换无迟到覆盖；本地模型保存/重开/撤销不依赖 DB，也不重放外部写入。
