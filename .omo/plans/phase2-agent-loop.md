## 补充评估：产品范围与设计原则

`/tmp/opencode/gui-flange.png`、`/tmp/opencode/screen_gui2.png` 只作为历史视觉材料，
不声称本轮已经完成真实 GPU 或新设计稿验收。E08 是确定的颜色接口错误，

### 1. 工作台视觉与交互

- 默认提供明亮工业主题：二维画布接近白色，三维画布为浅灰，面板有轻微层次；
  暗色作为完整备选主题。候选色板为画布 `#EEF2F6`、面板 `#F8FAFC`、文字 `#1F2937`、
  主操作 `#2563EB`、选择 `#F59E0B`，最终以实体/细线/标注实际可读性确定。
- 明确 Qt 颜色、GL 颜色、透明度的转换边界；相同颜色常量不能未经转换用于所有接口。
  文字、图标、焦点、悬停、选择、禁用、错误、欠约束各有状态规范，不只依赖颜色表达状态。
- 保持项目约定的左命令库、右结构/属性关系；按“二维绘图、草图编辑、三维建模、检查”
  切换上下文工具。中文任务名称作为主要入口，命令 ID 放在提示/高级区，保留检索能力。
- 底栏按任务展开，支持紧凑输入/收起和布局重置；默认避免大面积空白控制台挤占模型区。
  用矢量图标、必要文字、分组与一致的尺寸层级体现专业性，避免把信息密度误当成按钮堆积。
- 标准方向、正交/透视、工作平面、坐标轴、网格、捕捉、选择过滤和状态提示属于设计工具基础。
  不把文字按钮触发 JSON 参数框作为所有专业建模交互的最终形态。
- 普通建模显示 BREP 边界/轮廓，三角网格边只在诊断模式显示；配合柔和填充光、正确法线、
  锐边保留和遮挡策略。先验证现有渲染路线能否达标，再以原型证据决定是否更换显示后端。

### 2. 二维能力分层与三维操作

用户已明确确认“独立二维绘图与三维参数化草图都要”，该范围由规划假设转为已确认需求。
Gate C 必须分别验收独立二维绘图和参数化草图驱动三维的完整流程，不能以其中一项替代另一项。
原路线将草图约束主要放在阶段 3，本轮需求要求把有界基础能力前移，不能只补几个入口。

| 层次 | 阶段 2 主线 | 边界与后续 |
| --- | --- | --- |
| 独立二维绘图 | 直线/折线/圆/圆弧/矩形、精确输入、捕捉、修剪/延伸/偏移、变换、图层、基础标注、DXF 子集交换 | 复杂块/外部参照/完整样条编辑按场景扩展；DWG 不在本轮格式承诺内 |
| 参数化草图 | 可定位工作平面、上述基本图元、构造线、基础几何/尺寸约束、自由度与冲突反馈、闭合轮廓驱动实体 | 完整工业级约束、复杂曲线网络不是首批承诺；求解器选型与可重放性必须验证 |
| 关联工程图 | 不纳入 Phase 2 | 投影、关联尺寸、纸张布局、剖视/隐线、GD&T 等统一交 Phase 3 的 P3-38 范围决策 |
| 三维常规操作 | 草图拉伸/旋转、孔、圆角/倒角、布尔、移动/复制/镜像、线性/环形阵列、工作平面与历史改参 | 抽壳、拔模、扫掠、放样及装配进入 Phase 3 条件性范围决策 |

独立二维实体与参数化草图可共享图元和数值规则，但语义不同：普通标注不默认改变几何，
驱动尺寸会参与求解，参考尺寸只显示测量值。二维也需保存、重开、撤销与确定性重放，
不将屏幕像素、Qt 图形项或 SVG 当成几何真相源。几何/求解适配经端口隔离，保持 core 无后端依赖。

手工绘图应有“输入/选择—预览—明确应用或完成—提交”的连贯操作；
拖动和悬停属于临时交互，不能每移动一个像素就写历史或弹出一次计划卡片。
P2-00/P2-31 须明确手工操作的显式确认语义及审计，保留 Agent 的计划确认红线和唯一 Bus 写入路径。

- **P0**：状态正确性、执行授权及已确认的基础可视性缺陷；对应出口前必须完成。
- **P1**：阶段 2 主线，支撑流畅交互、设计检查和基础 CAD 交付。
- **P2（优先级）**：条件性扩展或方案决策；这些任务已移至 Phase 3，不是本阶段出口要求。
- 所有复选框初始为未完成；后续只有证据齐全才能勾选。观测缺陷和提出方案不等于实现完成。
- 每项 Todo 的“依赖”是硬前置；阶段收口另受本文件的 Gate 约束。优先级不代替依赖顺序。

长期不变量：

1. `core` 不引 CAD 后端、Qt 或 numpy；CAD 后端仅在 `geom`；Qt 仅在 `ui`；`app.py` 保持组合根职责。
2. 模型修改统一经 Command Bus，保留命令可重放和撤销重放语义。当前真实 API 是
   `execute / execute_batch / edit_and_replay / undo / redo`，不凭文档中的旧名称虚构 `submit()`。
3. 保留 v1 顶层结构、审计六字段及 amendments 追加语义；新持久化身份或快照需要独立版本决策和迁移。
4. 保留零类型抑制、统一 Ruff 规则、SPDX 和分层守卫；修订阶段性范围测试不能削弱长期分层规则。
5. 不更换 build123d/OCCT，不调整当前几何依赖 pin；升级应另有兼容证据和决策。
6. Agent 默认只生成受校验的声明式计划，不直接执行任意 Python，不自行生成用户确认凭据。
7. Python 插件仍属于显式信任的代码；manifest.permissions 不宣称具有沙箱强制能力。
8. 本轮将有界二维绘图、基础参数化草图和常规三维操作纳入主线；完整工程图、复杂约束、装配和
   云协同仍需独立范围决策。新增命令实施前通过 P2-00 明确释放保留 ID，不抢占命名空间。

阶段 1 的“无网络、无缓存、无线程、无打包”等是阶段范围约束。
对应 Todo 实施前，经 P2-00 明确新边界及 ADR/守卫迁移；本清单本身不修改现行 ADR 或解禁依赖。
P2-17 / P2-24 / P2-32 的 schema 扩展，以及 P2-10 的执行单元选型，需要先形成具体设计再实施。

本阶段仅放开基础 CAD 所需的缓存/执行单元等决策；新增模型网络调用、企业数据库驱动和远程集成由 Phase 3 单独决策。

### 六项优先设计收敛

这六项主要细化既有 Todo 的验收方式，不新增六个独立子系统。是否足以落在既有工作包
预算内仍需首轮实现校准；不能因“已有 Todo”就宣称新增交互没有成本。

| 编号 | 建议与具体行为 | 对应原任务 | 首轮边界/验收 |
| --- | --- | --- | --- |
| B01 统一操作流程 | 各工具沿用“选对象/基准 → 输入参数 → 预览 → 应用”，右栏给下一步提示，主要动作位置固定 | P2-16、29、31、36 | 预选与后选都可进入同一操作；取消不改模型；输入框 Enter 不误触全局命令；UI 草稿不替代已有 Plan 六态机 |

### 将“比 FreeCAD 好一点”变成可测结果

正式判断基于同一台 Linux 参考机、同一组尺寸和同等几何结果。
固定 MyCAD 提交与 FreeCAD 稳定版本；记录使用者熟练度、帮助、设置、任务顺序和失败。
先比较手工通道，再单独报告模板/AI 辅助通道，不将两类结果混为一个速度指标。

| 对比任务 | 核验结果 | 记录指标 |
| --- | --- | --- |
| 独立二维安装板，含孔/长圆孔、标注、图层、DXF 输出 | 单位、孔径/孔距、轮廓闭合和下游读取 | 完成时间、焦点切换、误捕捉/误选、帮助次数 |
| 约束草图驱动法兰或轴套，完成实体与 STEP | 约束状态、实体/尺寸、重开及导出一致性 | 完成率、工具发现时间、求助次数 |
| 板长 160 → 180 mm，保持厚度 8、四孔 Ø10 与孔距 120×60 | 每项保持条件确实成立 | 改参时间、需要手工修复的引用数、错误是否可察觉 |
| 制造约束冲突或非法圆角，再修复/取消/撤销 | 恢复原有效模型，无错误提交或损坏文件 | 定位错误时间、恢复时间、是否需重建零件 |

首批建议从 2～3 个企业设计团队邀请共 5～8 名目标 Linux 用户，并有数据/工艺管理角色参与，兼顾不同 FreeCAD 熟练度；
只记录试用方案，不在本轮联系或招募。交替任务顺序并提供同等起步指导，减少学习顺序偏差。
候选方向指标：固定任务的完成时间中位数降低约 20%，或帮助/误操作明显减少，
同时全部已支持任务保持尺寸正确、保存重开可靠。20% 是待校准目标，不是已有测量结果。
少量试用只能发现体验问题，不能证明总体市场优越性。

“有市场”的验证还要记录：用户是否愿意带来自己的真实零件、在随后一周再次使用、
是否能把导出结果用于现有流程、愿意为什么能力付费/贡献。
它们与漂亮截图、试用点赞和单次演示成功分开报告，暂不推算市场规模或收入。
